## 1. 判决

### **第 1 支 —— 「38~64 N」不是模型缺陷，也不是任何 z 差；开放项 C 可以关闭。**

一句话：**那个数是 `tol_M / |c_s_横向|` —— 力矩通道"能看见多大的 ΔFz"的探测下限。
它描述的是"一道假想的力矩门要多粗才看得见 z"，而力矩三个分量自 2026-09-21 起已经不投票
（`g_guardVote`）⇒ 那道门不存在。**

**⚠ 一句必须先说的话（对任务前提本身的更正）:** 计划 Task 6 写的是「开放项 C 记的是
"z 轴的缺口 ~38~64 N"」，Task 6 Step 2 又要求「列出能解释 38~64 N 的候选」。
**"能解释 38~64 N"这个问法预设了它是一个"差"，而仓库里没有任何文件把它记成差。**
它的三处落点（`.superpowers/sdd/runtime-guard-report.md` §3.1.1、
`ForceCompensation.cpp` 的 `g_guardVote` 注释块、`Config.h` 的 `FORCE_GUARD_TOL_FORCE_N`
注释块）**全部**是同一句算式：`ΔFz 要到 tol_M / |c_s_横向| = 38 ~ 64 N 量级，力矩通道才有机会
把它顶超限`。开放项 C 自己那一行的括注（"力矩通道也兜不住（`|c_s 横向|` 只有 0.5~0.8 mm）"）
也指向这个读法。**⇒ 候选 己（"38~64 N 本身是一个 z 差"）标为"不可判别"，因为它不是一次测量。**
本报告没有为这个不存在的"差"编造解释。

## 5. 判不出来的部分（明写）

1. **`A` 的第三行的绝对精度** —— 仓库里**没有** z 方向的力真值。§4 量到的是**与机械臂那套模型的差**
   （≤ 0.160 N），而 `A_臂` 由本项目早先下发的负载参数决定（`…-raw-channel-calibration.md`
   Task 8 / Task 9 ④⑤）⇒ **两者同错则看不出来**。另一个界是本地失拟 `eps_甲 ≤ 0.287 N`（夹具口径，
   前置复核 §7.2）。
2. **"看不见"的门槛** —— z 噪声 σ 是 `0.0189 ~ 0.0281 N`、5 个不同姿态 ⇒ 第三行斜率的 `se`
   是 `0.0010 ~ 0.0027 kg`。**低于约 0.05 ~ 0.1 N 的第三行误差，这三轮分辨不出来。**
3. **`@720` 在接触/外力下的行为** —— 无任何仓库文件验证过（前置复核 §4.2①）。
4. **`Fz` 不投票该不该改** —— 见 §4 第 3 条。
5. **一个建模假设（自审时发现，明写）** —— §4 的 `K = A_臂 − A` 这一步隐含
   "`@720` 与 `@1304` 在同一传感器坐标系、同一原点"（否则差里会多一个旋转/平移项）。
   仓库里**没有文件**直接确认这一点；间接旁证是 x/y 行的模也只有 `0.007~0.030 kg`
   （若坐标系不同，这三行不会都这么小）。**这一条是假设，不是文件。**

**⇒ 下一个能判别的测量（不需要动负载）:** 在同一批静态姿态上同时采 `@1304` / `@720` / `@576`，
姿态覆盖要包含"重力尽量落在传感器 z 轴"与"尽量落在 x/y 轴"两端，做**同一个** `K` 拟合，
判据是 `K`（`comp − @720`）的**第三行模**：仍在 `0.02 kg`（0.2 N）量级 ⇒ 维持"接受"；
显著变大（如 ≥ `0.1 kg` = 1 N）⇒ 第三行确实错了，那时再谈判据。
不需要动负载的理由：这一路比的是**两套模型的重力响应之差**，两者都靠**原地改姿态**激发，
负载参数一个字节都不用改。
