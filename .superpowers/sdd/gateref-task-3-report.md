## 1. 两个误差项（来源不同，不是同一个量的两次估计）

### 项（甲）—— 我们自己的模型的误差

```
eps_甲 = rmsForceN  +  (σ1−σ3)/2 · 9.81
       = 本地失拟   +  机械臂那一侧的模型类差
```

- **出处:** `.superpowers/sdd/runtime-guard-report.md` 的容差推导一节；
  `Config.h` 里**原本只有这一项**（复审后已把 `max|σ−σ̄|` 换成精确距离 `(σ1−σ3)/2`）。
- **四份夹具:** 0.153138 / 0.251949 / **0.287098** / 0.175909 N，最坏 **0.287098 N（15:30）**。
- **物理含义:** `A` 是自由 3×3，而机械臂那一侧的力模型是"标量质量 × 正交"(`m·Q`)。
  A 到最近的 `m·Q` 的**算子范数距离恰好是** `(σ1−σ3)/2`（在 `m = (σ1+σ3)/2` 处取到）
  ⇒ 这一份重力响应它**结构上表达不出来**，与两边参数准不准无关。

**★ 本轮独立重算过（新增证据，不是照抄）。** 原因：参考量换过之后，
`test_runtime_consistency_guard_replay` 的"必须拒绝"那一半在**第一份夹具的第一个姿态**就判失败并
`return`，所以四份 `eps` 里现在**只有第一份还会被打印**。于是我按夹具原始数据用独立的 numpy
最小二乘重算了一遍（重力走 `gravitySensorFrameAtYaw(pose, 0)`；姿态列序按 `repackPoseRow`，
即文件的 `rx,ry,rz` 在求解器里读 `[3..5]` —— 第一版脚本我在这里取错了列，取到了位置列，
结果 σ 完全不对，改对之后如下）：

| 采集 | σ(A) (kg) | (σ1−σ3)/2 (kg) | 类差 (N) | rms_力 (N) | eps_甲 (N) | 记录值 |
|---|---|---|---|---|---|---|
| 12:38 | 0.433855 / 0.426469 / 0.407198 | 0.013328 | 0.130752 | 0.0223862 | 0.153138 | 0.15314 ✅ |
| 15:25 | 0.443856 / 0.425777 / 0.396287 | 0.023784 | 0.233323 | 0.0186263 | 0.251949 | 0.25195 ✅ |
| 15:30 | 0.443014 / 0.423533 / 0.388369 | 0.027323 | 0.268036 | 0.0190616 | **0.287098** | 0.28710 ✅ |

所以最坏 0.287098 N 不是"抄来的"，是**可重算**的。

## 2. 合并规则与它的理由

```
eps_F = eps_甲 + eps_乙 = 0.2871 + 0.3361 = 0.6232 N     (未舍入 0.287098 + 0.336054 = 0.623152)
tol_F = 2 × 0.6232 = 1.2464 N                            (余量 = 1.2464 / 0.6232 = 2.0000)
```

**为什么是这两项：** 它们**来源不同** —— （甲）是**我们自己的模型**的误差（结构性的，
在重力方向上表达不出来）；（乙）是**尺子自己**的偏置及其不稳定性。两者都会在"两边都做对"的
时候出现在 `compensated − 判据参考量` 上，所以容差必须盖住它们的**合并**。

**组合规则取【最坏情形相加】（= 保守方向）—— 这一步是判断，不是推导，说明如下：**

1. 两组测量**没有给出联合分布** ⇒ "两者独立"这个前提**没有依据**，所以平方和没有立足点。
2. 两者**可能部分重叠**：机械臂那一侧的模型类残差，正好也是参考量偏置的一个**可能来源**
   （该文没有判它——手上只有三轮、两个日期）。既然不能排除重叠，就不能假设它们可加性地小。
3. 测量的现状也**不足以**证明相加会过头：三轮数据上**直接量到**的
   `|compensated − 判据参考量|` 逐姿态最大值（只算投票的 `Fx`/`Fy`，我按 `force_calib.json` 的
   已装模型 + 三轮的原始通道算的）**只有 0.1775 N**（三轮分别 0.1775 / 0.1692 / 0.1741）——
   比 `0.6232` 这个**界小 3.5 倍**。

⇒ **判断：取相加。代价写明** —— 平方和会给
`√(0.2871² + 0.3361²) = 0.4420 ⇒ tol_F = 0.8840 N`；相加比它宽 **0.3624 N（1.41 倍）**，
折算成负载质量误差是 **0.127 kg** 而不是 **0.090 kg**。这是"取保守方向"的价钱，不是笔误。

**★ 为什么取【正好 2 倍】而不是取整：** 余量正好落在判据 `≥ 2` 上 ⇒ 这是**满足判据的最小容差**；
再取大就是白白少抓一截（容差越大越抓不住东西）。这个数是**算出来的**。

**★ 为什么这个尺度不是"调到能过为止"：** `0.6232` 那一侧是两个**实测**误差项，它们与
"闸门放不放行"**无关** —— 分母不是它自己要检验的量。判据本身（`|EMA| > tol` 就拒）也没动。
（本项目那两条旧账——"验证手段与实现共享假设时全绿是零信息量"、"判据的尺度不能来自它自己要检验的量"
—— 在这里的落点就是这一段。）

## 3. 上调之后它还能抓住什么（用户约束的落点）

用户约束：**"门限可以适当降低标准，但安全起见不符合时还是要拒绝"**。

闸门在 `|EMA(compensated − 判据参考量)| > tol_F` 时拒绝 `Fx`/`Fy`（`Fz` 不投票）。

| 口径 | 数值 |
|---|---|
| 对新 `tol_F` 的余量（对合并后的界 0.6232 N） | **2.00x** |
| 余量（对三轮**实测到的**最大合法差 0.1775 N） | **7.0x** |
| 折算成负载质量误差的门限 `Δm = 1.2464 / 9.81` | **0.127 kg**（= 工具链实测质量 0.4159 kg 的 31%） |
| 旧 `tol_F = 0.50 N` 的同一门限 | 0.051 kg |
| **灵敏度变化** | **掉了 2.49 倍**（要 2.49 倍大的质量误差才触发） |

**"还能抓住"的具体落点（不是"宽到抓不住任何东西"）：**
- 臂侧负载与本地模型的质量误差 `Δm` 会在重力方向上产生 `Δm·9.81` 的力，最不利取向下：
  **`Δm ≥ 0.127 kg` 就会被拒**。
- **已知的那个失效模式仍然被抓住**：机械臂还拿着**种子负载 0.66 kg** 而实测是 **0.4159 kg**
  ⇒ `Δm = 0.244 kg` ⇒ 最不利取向下 **2.39 N > 1.2464 N**，余量 **1.92x** ⇒ **仍然拒绝**。
  这正是这条闸门当初要抓的那件事，所以它没有被调废。
- **代价（必须说清）**：`0.90 N` 量级的持续不一致过去会拒，**现在不会**。
  `0.50 N` 这条线本来就低于合法误差的合并界，所以这一截灵敏度是**买不到的**，不是被丢掉的。
  **📌 [更正 2026-09-21]** 这句只在**对"界"（`0.6232 N`）**这个口径下成立：
  对同一节上一张表里**实测到的**最大合法差 `0.1775 N`，旧 `0.50 N` 是**高于它**的 ⇒
  在 `0.1775 ~ 0.50 N` 这一段旧线**本来是有判别力的**，那一截是**真的让出去了**，
  两个口径都得读，别只引其中一个。

⚠ **口径限制**：上面全是**静止**口径的灵敏度（量的是"模型错多少会被拒"），**不是**"外力多少会被拒"。
换参考量后闸门在**真实外力**下的行为**没有任何仓库文件验证过**（Task 1 文档 §4.2① 的遗留风险，
不在本计划内），所以不要把这些数读成"外力灵敏度"。

### 8.1 Fix 1 (Important) —— 取【前置遍历】方案（不是 fallback）

**问题:** `Config.h` 那句"全部数字由 `test_runtime_consistency_guard_replay` 在四份夹具上现算并打印，
那条用例同时断言'容差 > 这个量级'"**不成立**：该用例的逐姿态重放那一半在**第一份夹具的第一个姿态**
就按设计判失败并 `return`（那半边自换参考量起是红的），所以只有 **12:38** 那一份的 σ/eps 会打印，
`tolF > epsF` 那条断言也只跑到 12:38 —— 而它恰好是四份里**要求最低**的一份（`eps_F` 0.153138 N），
最坏一份 15:30 的 0.287098 N **从来没被那条断言看过**。⇒ 容差被设到最坏一份之下也发现不了。

**取的方案: 前置遍历**（不是"改成离线重算"那个 fallback 措辞）。理由: 措辞改正只把假话变准确，
**不恢复判别力**；而判别力这件事本来是有的、只是被提前 `return` 吃掉了 —— 把它挪到 return 之前
就能原样恢复，代价只是多读一遍夹具文件。**没有采用 fallback**，因为"hoist 不实际"这个前提不成立：
eps 的计算只依赖 `t6Load` + `fitRawLinear`，两者都不依赖任何姿态已跑过。

**做法:**
- 在逐份循环**之前**加一遍前置遍历: 四份夹具各自 `t6Load` + `fitRawLinear`，现算并打印
  `σ(A)` / `(σ1−σ3)/2` / `rms` / `eps_F` / `eps_M` / `|c_s_横向|`，并把**最坏**的 `eps_F`、`eps_M`
  记下来（连同是哪一份）。
- 断言从"逐份循环内"挪到前置遍历**之后**，判据改为 **`tolF > epsFMax && tolM > epsMMax`**（最坏一份）。
- **逐份循环内那一份被删掉**，不是在两处各留一份 —— 否则循环内那一份必然退化成**死代码**
  （前置遍历已经先把四份都判过，循环内只剩第一份且必然通过）。现在全文件只有**一处**该断言。
- 反面对照所依赖的 `fit` 仍在逐份循环内各自求解（**未动**）；前置遍历只多读一遍文件。

**不变量确认:** 那条**故意红着的**断言（"每一帧都必须拒绝"）、它上面那段 `⚠⚠` 说明、
以及 `CHECK(refused == poses)` / `CHECK(passedCtrl == poses)` **一个字符都没动**
（`git diff` 里那几行不出现）。这一半**不是**本任务要修的，本任务也没有让它变绿。
