# 闸门误报修复报告 —— `test_session_report.cpp` 的"本地替库下结论"回归闸门

日期: 2026-09-19 · 分支: `feat/pen-clamp-redesign` · 底: `15d6060`

## 0. 一句话

上一轮把 `通过 / 拒绝` 当【无条件】结论词收进令牌表, 闸门于是对【明确拒绝下结论、把手指向库】的
句子误报 (复审实测五种)。本次把这两个词改成【只有箭头指着它时】才算结论 —— 六个漏网照旧全红,
五种递话写法全部转绿; 顺着查出并修掉三个附带的东西 (见 §4)。

## 1. 三个方向里选了哪个, 以及为什么不选另外两个

| 方向 | 判断 |
|---|---|
| **2. 砍掉裸的 `通过/拒绝`, 留箭头派生形** | **采用 (做实成"箭头指着判决词")** |
| 1. 结论词前不许有递话标记 (`不/未/否/非/见/以…为准`) | **不采用** —— 有具体反例, 见下 |
| 3. 要求两边都挨着数字 | **不采用** —— 六个漏网它保不住 |

**方向 1 的陷阱 (这是不采用它的具体理由, 不是口味问题)**: `不超过门限 X` / `未超门限 X` 是
【带否定前缀的判决】("没超过" = 过)。若按"前面有 `不`/`未` 就放行"实现, 一句**假通过**就大摇大摆
过去了 —— 而 `未超门限 X` 正是第一轮复审抓到、必须保持红的六个漏网之一。同理, 方向 1 列举的
`见`、`以…为准` 在本屏是**后置**的 (`通过与否以 [Payload] 行为准`), 按"前置"实现抓不住它们。

**方向 3 的算术问题**: 屏幕上的格式串是 `%.4g` —— 流里根本没有数字, 只有格式说明符。要求"数字在
两侧"要么把 `%`-格式串算成数字 (于是 `门限 %.4g 通过` 红、但 `在门限 X 以内` 的"以内"右侧没东西
→ 漏), 要么改造判据去理解 printf 语法。它保不住六个漏网中的 `在门限 X 以内`。

**实际做法 (方向 2 做实)**: 令牌分两类。

* **(甲) `kConcl`** —— 算子/结论词, 一旦出现就是结论: `< > ≤ ≥ 超过 大于 小于 低于 高于` /
  `越线 超线 过线` / `以内 √ 未超 未越 未通过`。与门限词挨着 (±10 字节) 就命中, 不看上下文。
  新增 `未通过`: 它是**不带箭头的否定式判决**, 补它是为了不把"拒绝"方向全押在箭头上
  (删掉裸 `拒绝` 之后, 拒绝方向就只剩箭头一条路了)。现网 main.cpp 里没有 `未通过`/`未超`/`未越`
  (已 grep), 所以是零风险净增。
* **(乙) `kPointed`** —— 判决词 `通过 / 拒绝`: **只有箭头指着它时**才算结论。
  与门限词挨着**且**前面紧挨着一个箭头 (中间只允许空格与 `【`/`[`) 才命中。

配套改了箭头处理: `withoutArrows`(删掉箭头) → `neutralizeArrows`(整根箭头换成一个中性标记字节
`0x01`)。**这一步是必需的, 不是装饰**: 箭头删掉之后 `门限 %.4g -> 通过` 与 `门限 %.4g 通过与否以…`
在流上长得一模一样 —— 而它们意思相反。上一版正是看不见这个区别, 才只能把 `通过` 变成无条件令牌。
标记字节同时满足两件事: 它**不是算子** (`-> 见 [Payload] 行` 不再被那个 `>` 假命中), 又**仍然看得见**
(箭头指着谁可以被单独判 → 那五种递话写法有救了)。

*为什么标记是 **1 个字节**而不是"保持原长"或"0 个字节"*: 0 字节 = 就是上面那个失效的版本;
原长会把箭头两侧按箭头宽度推开, `→` 宽 3 字节, 实测把 `门限 %.4g → 通过` 里的"通过"正好推到
窗口右界 `p+16` 上 —— **差一个字节就漏** (这一版我第一轮实现就是这么漏掉 `→ 通过` 的, 见 §5)。
压到 1 字节 = 与上一版的相对距离几乎一样, 但算子那件事不再假命中。

  读那段注释不可。实测代价: 本屏写结论用的形状是 `-> 通过`, 裸 `通过` 不是本屏的写法。

## 3. 顺带: 把"误报"这一类写进文档 (本次缺陷的成因)

原文档只枚举了**抓不住**什么, 一个字没写**误报**什么 —— 所以没人看见这一次加词的代价。现在:

* 新增"**第二轮复审**"整段: 五种误报逐条列出, 加上"结论在逗号(1 字节)/`——`(3 字节)/箭头之间翻转"
  这个对照 (`门限 %.4g —— 通过与否见 [Payload] 行` 当时是绿的), 以及**为什么它比原缺陷更坏**
  (下一个人会把令牌表砍掉, 于是六个漏网重新打开)。
* 新增"**余量**"一段, 都是**实测数字** (2026-09-19):
  * 窗口 W = 10 字节。
  * 现网最紧的一对**合法**搭配是 **43 字节** —— `main.cpp:1346` 的
    `↑ 【不参与任何接受/拒绝判据】: 它来自拟合残差, 拿它当门限就是自指` 里 "拒绝" 距最近的门限词
    43 字节, **余量只有 33 字节**。判决词改成"要箭头指着"之后这一类不再有窗口问题。
  * 但 (甲) 的算子**同样有这个暴露面**: 现网里算子距门限词最近的一对是 **100 字节**
    (`≥5 对` 与 `3n−12 要 > 0` 那两处, 余量 90 字节; 本屏合法地印 `≥5 对` 两遍)。
    措辞: "改这一屏时若把某个 `>`/`≥` 挪到离'门限'二字 10 字节以内, 那**不是**误报 —— 只要它比的
    是门限, 这条闸门本来就该红; 但它若在说别的事 (自由度、配对数), 就得回来把 W 或令牌表重新想一遍,
    **而不是**把令牌砍掉。"
  * 这两段数字是**新加的用例**钉住的: `本屏3` 那条把 43 字节那两句**逐字**喂进去并断言绿 ——
    谁要是把判决词重新变成无条件令牌, 或者把 W 拉大到 43 以上, 它立刻红。

## 4. 另外三处

1. **`force/PayloadCalibration.cpp:1288-1290` 那句「现在两个标志同进同退」** (对**值**已假):
   `:1291` 无条件置 `modelFormChecked = true`, `:1292` 置 `momentFormChecked = (lackOfFitMomentDof > 0)`
   —— 两者**恰好在 dof == 0 处分岔**, 而客户端正是按这个分岔分两支的。已改为一句话说明
   **两者不同进同退 / 在 dof == 0 处分岔**。**行数保持 3 行不变** —— 因为 `main.cpp:1391-1392`、
   `main.cpp:1469` 与本测试都按**行号**引用 `:1291-1292`, 加行会把那些引用指错 (而 `main.cpp` 本次
   不许改)。改后 `git diff` 是 3 增 3 删。

2. **闸门没钉工作目录** (它按相对路径读 `../main.cpp`): 已钉。`main()` 第一件事
   `pinCwdToTheExeDirectory()` (用 MSVC CRT 的 `_pgmptr` 取 exe 目录, 两个 `.bat` 本来就 `cd` 到
   `tests/`, 行为不变); 另加 `readMainCpp()`: 真读不到源文件时**先把环境问题喊出来**
   (「⚠ 环境问题, 【不是】闸门判决: 读不到 ../main.cpp (工作目录 = …)」), 不让它冒充一次判决。
   *实测到的实际情况比预想的更坏*: 改前从 `C:\` 或 `D:\Projects\Touch\Docs` 跑那个 exe,
   **退出码 `0xC0000409` (STATUS_STACK_BUFFER_OVERRUN / fail-fast), 输出一个字都没有** (stdio 缓冲
   随进程一起没了) —— 不是"看起来像闸门失败", 是**静默死掉**。改后从 `C:\` 跑: `20 passed, 0 failed`。
   (机制未定位: 只确认它随 cwd 变化, 不随 exe 变化; 钉住 cwd 之后不再出现。)

3. **没做**: 把闸门接进 `tests/run_tests.bat`。判断理由两条: (a) 那个列表是**固定的历史子集**,
   `test_payload_calibration` / `test_calib_store` 等新版独立测试都不在里面 —— 单独塞一个进
   去是"改套件语义", 不是修闸门; (b) 更要紧: `run_tests.bat` 对"exe 不存在"是记 `FAILED` 的,
   而这条闸门**是一道绊线, 有真实的误报面** (它按文本扫, 改 `main.cpp` 别的行也可能碰到它) ——
   在它刚因为误报被复审过的时候把它接进默认套件, 是把误报的代价**乘上**每一次无关改动。
   要接的话应当连着建 e 步一起接, 是另一件独立决定。

## 5. 没能验到的 / 已知残余

* **闸门读的是源文本, 不是行为**: 它钉的是"那句话怎么写"。`solveAndApply` 跑起来在实机上印什么,
  本次**依旧到不了** (要实机数据), 与上一版同一局限。
* **`门限 X 通过` (无箭头) 是明写的洞** (G9)。代价见 §2.2。
* **箭头指着递话句的混血写法仍会误报** (例如 `门限 X -> 通过与否见 [Payload] 行`): 箭头指着判决词,
  规则就命中。那种句子读不通 (箭头是"结果是…", 后面跟一个问句), 所以**没有**为它再收窄 ——
  按上一次的教训, 为一个不存在的句子加规则, 只会多一个盲区。写进注释了。
* **别的箭头字形** (`⇒ U+21D2` / `➔` / `⟶`) 与英文措辞仍在盲区 (G8 钉住英文那条)。
* **中间过程被我改过两次**: 第一版实现是"箭头占位但**长度不变**", 实测 `门限 %.4g → 通过` 因为
  3 字节箭头被推到窗口右界 `p+16` 上而**漏掉** (测试当场红, 见用例 `漏网2`); 改成 1 字节标记后
  `→ 【拒绝】` 又因为 `【` 占 3 字节而漏; 最后把窗口锚到箭头上才全绿。**这两次都是测试先红**,
  不是事后补的理由。
