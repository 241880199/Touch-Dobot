# 调零与负载标定流程（换装笔夹后）

> 三个参数、三份标定文件，**全部由实机测出来**，不写死在代码里。
> 本文是上机操作手册；原理注释在对应源码里。

---

## 0. 为什么要做这一步

`Touch_Client` 从 30004 端口 offset 576 读的是 **`ActualTCPForce`**——机械臂**已经做过重力/惯性补偿之后**的净力。机械臂做补偿所依据的"末端负载"来自我们下发的 `EnableRobot(load, centerX, centerY, centerZ)`。

所以负载参数不准时：

1. **残余重力随姿态漂移**。单姿态 TARE 只能扣掉某一个姿态下的常量偏置，换个姿态又冒出来。
2. **碰撞检测误触发 / 拖拽失控**（`Docs/机械臂资料/Dobot CR3机械臂参数文档.md` §负载设置明确写了这一点）。

换笔夹之前，代码里是硬编码的 `EnableRobot(0.5,0,0,0)`。现在笔夹 + 双钢光轴 + 笔的重量和质心**都变了**，这个值既不等于实际质量、更没反映质心位置。

---

## 1. 三个参数、三个来源

| 参数 | 权威来源 | 怎么得到 | 兜底 |
|------|---------|---------|------|
| 末端负载（质量 + 质心） | `payload_calib.json` | 实机 `'m'` 采集 → `'s'` 求解 | `Config.h` 的 `ROBOT_PAYLOAD_SEED_*` |
| 力传感器零偏 | `force_calib.json` | 实机 `'z'` 调零 | 无（没有就该调零） |
| 笔尖 TCP 偏移 | `tcp_calib.json` | 实机 `'t'` 采集 → `'s'` 求解 | 无 |

**`Config.h` 里的负载常数只是"种子"，不是权威值。** 它存在的唯一理由是：第一次启用机械臂时还没有任何实测数据，而 `EnableRobot` 必须先给一个负载才能使能。标定过一次之后，`payload_calib.json` 说了算，启动时自动加载。

想先看看种子值是怎么估的（改硬件后可以复核）：

```bash
python Hardware/tools/compute_payload.py        # 读 STL 算体积+质心, 叠加已知件质量
```

它给出的是**量级参考**（当前 ≈0.66 kg、质心在法兰下方 ≈80 mm），用来判断实机解出来的结果是否离谱。

---

## 2. 启动自检

启动 `Touch_Client.exe`（联机模式），确认控制台：

**第一次**（还没有 `payload_calib.json`）：

```
[Payload] 无 payload_calib.json — 用种子值 mass=0.66kg com=(0,0,80.4)mm
          实机标定: 启动后按 'm' 采多姿态 → 's' 求解
[Relay] 使能 EnableRobot(0.660,0.0,0.0,80.4)  (种子值, 未标定)
```

**标定过之后**：

```
[Payload] Loaded payload_calib.json (mass=0.657kg, com=(0,0,80.4)mm, 6 poses, sign_z=+1)
[Relay] 使能 EnableRobot(0.657,0.0,0.0,80.4)  (实机标定值)
```

力线程收到第一个 30004 包时还会**回读机械臂实际采纳的负载**：

```
[Relay] 机械臂实际负载: load=0.657 kg  center=(0.0, 0.0, 80.4) mm
```

`EnableRobot` 的返回码只能说明命令语法对了，不代表机械臂真采纳了——这一步才是真检查。若回读值与下发值不符，会以 `!!` 打红字，**先查这个再往下做**。

---

## 3. 标定末端负载（核心步骤）

### 3.1 采集（`'m'`）

1. 让笔尖**悬空**（不要碰桌面/纸），把机械臂摆到一个方便绕腕部转的姿态。
2. 按 `'m'` 进入模式。
3. **摆姿态用 `'d'`**。进入 `'m'` 后机械臂是**锁定**的（不会自动变柔顺），按 `'d'` 才进入拖拽模式，可以手动拖。
4. **保持位置不动、只改姿态**（绕腕部转，笔尖大致还在原地）。摆好一个姿态后：
   - 按 `'d'` **关掉拖拽**（`Drag mode OFF — 位姿锁定`）——**这一步不能省**，
     拖拽中机械臂是柔顺的、姿态会漂，开着采样采到的力数据是脏的；
   - 再按 `SPACE`，采样 1 s 后写日志。
5. 采 **6~8 个姿态**，**笔朝下 / 水平 / 朝上都要有**（原因见 3.4）。

> 拖拽模式也可以在退出 `'m'` 时自动关闭——按 `'m'` 退出、按 `'s'` 求解、
> 或切到别的采集模式（`c`/`t`/`v`/`k`/`z`）都会自动关掉，不会把柔顺状态漏出去。
> 没有示教器时就用 `'d'` 摆姿态。

### 3.2 求解（`'s'`）

按 `'s'`，程序做四件事：最小二乘求解 → 换算成绝对负载 → 存 `payload_calib.json` → **重新下发 `EnableRobot`**。

```
======================================================
  负载参数求解结果 (6 个姿态, CZ 符号约定 +1)
======================================================
  质量:    当前 0.660 kg   →  修正 +0.003 kg   →   0.663 kg
  质心 X/Y/Z: 当前 (0.0, 0.0, 80.4)
             修正 (-0.0, +0.0, -1.2) mm
             下发 (0.0, 0.0, 79.2) mm
  拟合残差: 力 0.0214 N   力矩 0.0013 N·m
------------------------------------------------------
  已保存 payload_calib.json (下次启动自动加载)
  → 请再按 'm' 采 3~4 个姿态【复验】, 看残差是否掉到噪声本底
    若残差反而变大 → 说明机械臂解释 CZ 的符号与我们假设相反:
      按 'i' 翻转符号约定 → 重新 'm' 采集 → 再按 's' 求解
```

**修正量是带符号的**——直接告诉你往哪边调、调多少，不需要试。

### 3.3 复验

按 `'m'` 重新采 3~4 个姿态。看 `跨姿态极差`：应该掉到**噪声本底**附近（第一次跑时把当时的 `|ΔF|`/`|ΔM|` 记下来当本底；同一个姿态连采两次，两次之差就是本底）。

判据：

| 项 | 通过 | 说明 |
|----|------|------|
| 姿态跨度 | ≥ 30° | 不足则**不判定**（极差只是噪声） |
| 倾角 `sinθ` | ≥ 0.5 | 不足则质心项**不可观测** |
| `\|ΔF\|`（力） | ≈ 本底（< 0.3 N） | 力项大 = 质量不准 |
| `\|ΔM\|`（力矩） | ≈ 本底 | 力矩项大 = 质心不准 |

### 3.4 为什么姿态要摆到水平/朝上

报告把**力和力矩的极差分开统计**，因为：

- **质量**误差 `Δm` 会**同时**污染力通道和力矩通道（力 `ΔF = Δm·g`，力矩还会经 `p_cfg` 漏进去）；
- **质心**误差只体现在力矩通道——反过来，力矩通道是唯一能反映质心误差的通道。

而这个力矩响应 ∝ `sinθ`（θ = 工具轴与重力的夹角）。**笔一直朝下时 θ≈0，轴向质心误差在力矩上不产生任何响应**——报告会直接标"不可观测"，而不是给你一个假的小数字。所以务必把笔摆到水平、甚至朝上各采几个。

### 3.5 CZ 符号约定不对怎么办（`'i'`）

我们下发的 `centerZ` 与机械臂内部实际使用的值可能差一个符号。**如果假设反了，解出的修正量不是把误差抵消掉而是翻倍，迭代会发散**——所以符号必须对。

判定方法（一次就能看出来）：求解并下发之后复验，**残差变小 → 符号对**；**残差反而变大 → 符号反**。

符号反了就按 `'i'` 翻转约定，然后**重新 `'m'` 采集**再 `'s'` 求解（旧数据是在旧配置下采的，翻符号后作废）。符号对了，一次求解即收敛。

翻转会写进 `payload_calib.json` 的 `com_sign_z`，下次启动自动生效。

---

## 4. 调零（`'z'`）

负载参数对好之后，残余的就只剩一个与姿态无关的常量零偏，这时调零才有意义。

1. **保持机械臂静止**（笔尖悬空，别碰任何东西）。
2. 按 `'z'`。
3. 静置采 2 s，自动定稿、应用、存盘：

```
[Force] ZERO started — keep robot still for 2s (TARE only: no motion phase, drag mode NOT enabled)...
[Force] TARE done: biasF=(-0.482, -1.351, -0.021) N  biasM=(...)
[Force] ZERO complete (mass 0.0000 kg kept): force bias=(...) N, torque bias=(...) Nm
[Force] Saved force_calib.json
```

看到 `Saved force_calib.json` 就成了。

- **不会进入 MOTION 相、不会开拖拽模式**（旧流程按 `'c'` 后 2 s 机械臂会自动变柔顺，很容易吓一跳）。
- 中止：再按一次 `'z'`。**中止不写盘**，零偏保持原值。
- 可以反复调零，同一进程内不用重启。
- ⚠ 程序检测到保留的惯性补偿质量 > 0.05 kg 会打 WARNING——那是"该重标质量"的信号，不是调零该解决的问题。

---

## 5. 复验与收尾

1. 再按 `'m'` 采 3~4 个姿态，看 **MATLAB 力面板上补偿后的读数各姿态是否都 ≈ 0**。
   > 注意区分：3.3 步看的是 **raw 的极差**（判负载参数对不对，横着比）；这一步看的是**补偿后的绝对值**（判零偏扣干净没有，竖着比）。
2. 通过后回硬件计划 `Docs/superpowers/plans/2026-09-02-force-feedback-writing-demo-hardware.md` 的 Task 4（坐标标定）继续。

## 键位表

| 键 | 作用 | 开拖拽模式 |
|----|------|-----------|
| `m` | **多姿态采集**（标定负载）；`SPACE` 采一个姿态 | 否 |
| `d` | 在 `'m'` 模式下：**拖拽模式开关**（摆姿态用，见 §3.1） | 开/关 |
| `s` | 在 `'m'` 模式下：**求解负载参数**并下发存盘 | 否 |
| `i` | 在 `'m'` 模式下：翻转 CZ 符号约定 | 否 |
| `z` | **调零**（仅 TARE：静置 2 s → 应用 + 存盘） | 否 |
| `k` | 力标定全流程（TARE + MOTION 拖动拟合质量） | 是 |
| `c` | Touch→Robot 坐标标定；`s` 求解 | 否 |
| `t` | TCP 偏移标定；`s` 求解 | 否 |
| `v` / `f` | FK 实机验证 / 输出分析报告 | 否 |
| `e` | 手动脱困 | 是 |
| `q` / `ESC` | 退出（自动下使能） | — |

> 六个采集类模式（`c`/`t`/`m`/`v` 等）互斥：进入任一个会自动关掉其它的。它们都靠 `SPACE` 采点，同时开着会互相吞按键。
