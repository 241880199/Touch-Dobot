## 2. 用户发现的两个问题

### ① 位姿 5、6 采样时**没有锁定**（拖拽仍开着）

机械臂处于柔顺状态 → 采样那 1 秒内位姿在漂 → **记录的位姿与平均出来的力对不上** → 系统性误差。

**证据吻合:** `pair3`（位姿 5,6）的 `力z: d=+0.0603, σ_rep=0.0427`，明显大于其它对。

### ② 但这解释不了全部

`pair4`、`pair5` 的 `d` 与 `σ_rep` 也很大（`-0.0667/+0.0705`、`0.0471/0.0498`）。
**整个会话的尺子都被抬高了**（姿态级 `0.0273 N` vs run 001 的 `0.0233 N`）。

> ⚠️ 这一点要注意: **尺子被抬高会让【力通道】更容易通过**。
> 所以力通道那个 `1.024` 要打一点折扣 —— **而力矩通道是在尺子被抬高的情况下仍然失败**, 信号更强。

## 4. ⚠ 一个要留意的现象：`m` 与 `c_s` 在**采集之间**漂

```
m     : 0.422357 → 0.421585 → 0.417746     (跨度 1.1%)
c_s_z : 54.55    → 55.556   → 56.064       (跨度 2.8%)
parity: −1        → −1       → −1           ✓ 稳定
```

**而每次自己报的不确定度只有 0.33~0.4 mm（`c_s`）。**

→ **采集之间**的差异比**采集之内**的不确定度**大一个量级**。这本身是个信号，
说明存在**未被建模的、跨采集变化的**因素（温度？装夹重复性？零点漂移？）。

## 5. 决定性的下一步：**全锁定重跑一次**

这是唯一能把"程序问题"与"力矩模型问题"分开的实验，而且很便宜：

| 重跑结果 | 结论 | 下一步 |
|---|---|---|
| 力矩失拟**回到 ~5** | ✅ **是程序问题**（那两个姿态没锁） | 继续往下走（Task 9 坐标系对账） |
| 力矩失拟**仍是 ~20** | ❌ **力矩模型有真问题** | 首要嫌疑: **力矩的参考点** —— 模型假设力矩绕**传感器测量原点**, 这一条**从未验证过**（见算法评审列的六项预设之一） |

**操作:** 全程按 `'d'` 锁定后再 SPACE，**每次采样时确认控制台已打"位姿已锁定"**；
对与对之间换姿态。
