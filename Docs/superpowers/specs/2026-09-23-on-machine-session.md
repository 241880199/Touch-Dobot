## 三、当晚查出的三个**静默**缺陷

### 3.1 `RP|` 解析下标错**一个字符** ⇒ 面板两行恒 0（**已修 + 已验证**）

`relay_gui.m`：`startsWith(msg,'RP|')` 之后写的是 `msg(3:end)`，而 `'RP|'` 是**三个**字符
⇒ 载荷从 `|` 起、`sscanf('%f,…')` 撞非数字**立刻返回空** ⇒ `length(vals)==6` 恒假
⇒ **`S.robot_pos` 一次都没被赋过值**。

**代价两处，都静默**：面板 `Position` / `Orientation` 两行恒 0（现场报告"orientation 恒为 0"）·
3D 里 `eeMarkerActual`（实际位置球标）被 `if any(rp(1:3)~=0)` 挡住 ⇒ **从未显示过**。

**证据**：headless 实测 `sscanf('RP|12.34,…'(3:end))` 长度 **0**、`(4:end)` 长度 **6**。
同文件 `RG|`（也是三字符）早踩过并写下警告，**本支漏修**；`FB|`（三字符）是对的。
**C++ 侧已排除**：`robotActualPose` 唯一周期性写入者是 `queryPose()`、`tcpPoseActual` 从不拷进它，
而日志里 `pos=`(GetPose) 与 `tcp=`(30004 帧) **30/30 逐位相同**且跨运行变化 ⇒ `RP|` 确实发出去了。

### 3.2 `sendRelayUpdate` 帧界 bug ⇒ **静默丢消息**（**未修**）

它**分两次 `send()`** 发（消息 + `"\n"`）、**无锁**、而**两个线程**都在调
（触觉线程发 `P|`、主线程发 `RP|`/`J|`）⇒ 交错时**换行丢失、下一条被粘上**：

```
L|274.9,311.9,68.6,331.2,275.8,300.1P|0.00,-65.51,-88.11,-23.50,6.60,14.92
                                    ↑ 第二条对 MATLAB 而言【不存在】
```

**实测：109568 行里 54 行如此**（≈0.05%）。修法：整行（含换行）**一次 `send`** + 跨线程加锁 /
循环写完（`send` 的返回值也不该只判 SOCKET_ERROR —— 短写同样会截断）。

### 3.3 我自己加的旁路日志把 MATLAB 界面卡死（**已修**）

现场报告"按住按钮时界面卡死、松手才恢复"。机制：`tlog` 每条一次 `fopen/fprintf/fclose`，而它跑在
**收包回调**里（正是服务界面的那条线程）；实测 **~39 条/秒 ⇒ 上百次文件 I/O/秒** ⇒ 界面被饿死；
按钮一松、`C|ServoP` 停了、消息率骤降就"活了"。
**⚠ 这是"测量工具扰动了被测对象"** —— 改法是降开销，不是少测点：
持句柄写 + **每秒 `close`/`reopen` 一次**（⚠ 实测 `fseek(fid,0,'cof')` **不刷新** —— MATLAB 还在跑时
另一进程读到空文件，只持句柄会让实时读取失效）+ **同内容去重**（`W|` 是设计上 30 Hz 重发、21 条/秒
且文本逐拍相同 ⇒ headless 实测 300 条输入→124 行，信息不丢）。
顺手把 `P|`/`J|`/`RP|` 从"一律不记"改成**抽样记**（每 10 条 1 条）—— 全滤掉会让日志**回答不了**
"这几路到底有没有到"，而 3.1 正是卡在这里。

**验证**：`checkcode` **19 → 19**，逐条同分布（过程中引入的 `now`、"未使用持久变量"两条 lint 被它抓出并修掉）；
现场确认重载后卡死消失。

## 四、按钮2 姿态映射：**本趟测不出来，根因是钳位饱和**

### 4.1 为什么测不出来（数据）

在用户完成四组动作（纯平移 / 点头 / 摇头 / 捻笔）后：

| 量 | 实测 |
|---|---|
| `\|rx\| > 170` 的样本占比 | **85.8%**（550/641） |
| rx 取值分布 | **+180 出现 208 次、−180 出现 117 次**（325 次精确落 ±180）⇒ **一直在接缝上翻转** |
| 最小二乘系数 | 全部 ≤ **0.07**（角与位置两块都是）⇒ 环**饱和**，无信息 |

⇒ **关于 rx 的部分全部不能用**；关于 ry/rz 的部分（用户的两条定性观察）**不受此钳位影响，仍有价值**。

**机制**：用户挪到的位姿是 `rx = −147.82`（**离接缝只有 32° 余量**），而姿态摆幅 ±50~80°
⇒ 几秒内撞到 ±180 被 `clampOrientToBounds` 夹住并**钉死**（那 325 次精确 ±180 + 反复翻转就是指纹）。

**更麻烦的**：这台臂做这个活时末端姿态**天然就在 rx ≈ ±180 附近**（笔朝下）⇒ **可能是
"操作员在 ±180 附近转不过去"的根源**。⇒ **要测出映射，先得处理这个钳位**（`SAFE_R*` 没有出处、
09-22 "环绕/规范化"那条修法现场撞出关节超速并已回滚留档）。

### 4.2 用户的定性观察（**照原样记，附适用边界**）

1. **纯平移 ⇒ 机械臂动了**（设计说应当不动）—— ⚠ **要打问号**：环饱和时无法区分"位置真的漏进姿态环"
   与"饱和产生的假象"，需在不饱和的环里重测；
2. **② 点头 与 ③ 摇头 的实际运动方式应当对调**；
3. **④ 捻笔 ⇒ 机械臂沿 y 轴运动，且没有自转现象**。

### 4.3 ★ 一条**不需要机器人**的测量捷径（下次先用它）

**笔杆的姿态角 `P|` 的后三位与机械臂无关** ⇒ 只要读 `P|`，让操作员把笔按**左/右摆、前/后摆、自身
