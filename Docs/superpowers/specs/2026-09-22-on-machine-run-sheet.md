### ★ 操作细化（2026-09-22 按代码核过时机）

**先明确一件事：SPACE 不是"取当前值"，它是开一个 1 秒的窗口。**
`BiasCheck::record()`（`main.cpp:262`）按下后只做两件事：开窗、打
`[BIAS] 采样 1000ms — 保持静止...`；**真正打印在窗口结束时**的 `sample()`（`main.cpp:335`）。
而 `笔杆姿态` 取的是 `appState.stylusOrient` 的**那一刻快照**（由 haptic 回调每帧更新的
**绝对**朝向 —— 与按钮按没按、机械臂动没动都无关）。

**⇒ 不要"边转边按"。** 步骤：

1. `m` 进模式（会打出模式提示，确认看到 `[BIAS] Mode ON`）。
2. **按住按钮2**，用**很慢**的速度转动笔杆，扫过一段较大的角度。
3. **盯机械臂**：记下**晃得最凶**的那个朝向（现场症状是"缓慢也大幅晃、范围越走越大"）。
4. **在那个朝向上把笔停住**（按钮2 保持按住或松开都行 —— 读数只跟笔的姿态有关，与按钮无关）。
5. 按 `SPACE` → **等窗口跑完**（会先打 `采样 1000ms`，再打结果块）→ 读那行
   `笔杆姿态 Rx=… Ry=… Rz=…`。
6. **再取一个"明显不晃"的朝向，同样按一次 `SPACE`** ——
   **有对照点才判得了"±90° 才退化"；单点读数说明不了任何事。** 建议 2~3 个点。
7. 三根轴都扫一遍（别预设是哪一根）—— 判据只看 `Ry`，但"哪个朝向开始晃"要你自己找。

## ★★ 当晚追加：姿态接缝抖动（**已定性确认**，并已实施最小修法）

### 现场结论（用户 2026-09-22 实测）

按住按钮2，**朝 +rx 方向滚过 ±180** ⇒ 机械臂在**该点附近抖动**；**同一姿态往 −rx 反向 ⇒ 不抖**。
判别性证据 ⇒ **成因就是姿态边界钳位 `clampOrientToBounds`**（`RelayCore.cpp`）。

控制台实录（用户提供）：
```
[Safety] Orientation target out of bounds, clamped. Original: (183,-2.76643,15.5627)
```
**机制**：`183 − 180 = 3.0` **恰等于 `ORIENT_MAX_STEP_DEG`** ⇒ `m_targetOrient.x` 已顶在 180、每帧被夹回
⇒ 手的抖动让目标在"被夹到 180"与"落回 180 以下"之间**逐帧来回** ⇒ 指令以帧率往复 ⇒ 臂抖。
往 −rx 推时 `desired.x` 单调减小、**永远碰不到墙** ⇒ 不抖。

**根因**：`m_targetOrient` **从不 wrap**，而钳位比的是**绝对值** ±180 ——
而 **±180 只是 RPY 表示的接缝，不是机械臂的危险姿态**（J6 量程 ±360）。

### 顺带查明：三个 `SAFE_R*` 没有出处
`Config.h` 里 `SAFE_RX/RY/RZ` 的注释只有"安全限位"四个字，**没有推导** —— 像是照角度满量程抄的。
⇒ **"它们该是多少"这个问题未解决**，已列为待办（别在一个没有依据的数上做安全设计）。

### 同趟排除掉的两条（各有实测，别再来回猜）

1. **不是虚拟力**：三路约束力**只写进触觉设备、不向机械臂下发任何字节** ⇒ 按构造不可能让臂抖；
   开关也关着；现场那帧 `comp` 逐轴 ≤0.12 N，过不了 0.20 N 逐轴死区，闸门 OK。
2. **不是腕部奇异阻尼**：拿现场关节角调**生产代码** `dampOrientationMotion` ⇒ `β = 1.000000`
   （扫球 2664 方向取最小 + **迹法** `β = Σ damped(eᵢ)·eᵢ − 2` 交叉核对，两法一致）；
   **邻域 J4/J5/J6 各 ±60°、共 15625 个位形，`β < 1` 的一个都没有**（`J5=95.3°`，整个避开奇异带）。

### ★ 另查出一条独立缺陷：肩部安全推离**恒在满档**

`robot/Kinematics.cpp` 的 `computeJointPositions`，**J2 那一段只有旋转、没有平移** ⇒
`positions[2] ≡ (0, 0, J1_Z)` ⇒ **`r_elbow ≡ 0`（任何关节角）**（实测 `pos[1] == pos[2] == (0,0,136)`）。
而肩部安全判据正是 `r_elbow < 120mm` ⇒ **恒落红区（<50）⇒ 每次满档** `tcpAdj=(5,0,0)mm`、`repulsion=(3,0,0)N`。
**⇒ 它是不分位姿的常量，既保护不了什么，也解释不了"在某点附近"。**
**可证伪预测**：MATLAB Safety 面板应当**一直**显示 `TCP距Z轴过近，已最大力度外推`。
⚠ 该取的索引很可能是 `positions[3]`（实测 r = **139.07 mm** ⇒ 不该触发）。**这条今晚不改**（改下发行为，要配测试+复审）。

### 已实施的最小修法（**实验**，回滚 = 一行）

**开关**：`Config.h` 的 `ORIENT_SEAM_FIX_ENABLED`（`false` 即恢复原行为）+ `ORIENT_MAX_OFFSET_DEG = 150`。
**两处改动**（都在 `RelayCore.cpp`）：
1. `:1093` 的钳位改成 `clampOrientOffset(m_targetOrient, m_orientRefRobot)` —— **比相对参照的偏移**，
   而不是绝对值（那才贴合"别相对起始姿态转太多"的意图）；
2. 下发 `ServoP` 前把三个角 `normalizeDeg180` 到 `[−180,180)` —— 规范化是**等价朝向**（183 ≡ −177）。

   ⚠ 不需要"最短路径角差"：目标不 wrap、`desired` 也连续 ⇒ 差值本来就是小数。

- 按 RPY **直接解释** ⇒ 会命令 **J6 转一整圈**。

**⇒ 那个"未验证前提"有答案了，而且是坏的那一支：控制器【不】把 RPY 当模 360。**

`ORIENT_MAX_OFFSET_DEG` 与 `clampOrientOffset` / `normalizeDeg180` **保留**，

⇒ "姿态边界该是多少 / 该用什么机制表达"是一个**未立项的设计问题**。

### 机制（正面匹配，不是推导）

被判门限的量是 **"相对按下按钮2 那一刻的绝对偏移"**（`RelayCore.cpp` 的 `offx/offy/offz`），
门限 `ORIENT_DEADZONE_DEG = **0.05°**` —— 而手抖是 **≤1°**：

| 量 | 值 |
|---|---|
| 平移时笔杆姿态摆幅（实测） | **≤ 1°** |
| 门限 | **0.05°** |
| ⇒ 门限比手抖小 | **20 倍** |
| ⇒ 偏移在门限两侧穿的幅度 | 每帧最多 **~1°** 的姿态指令闪烁 |

⇒ `drx/dry/drz` 在"原样放行"和"置 0"之间**逐帧闪** ⇒ 姿态指令以帧率往复 ⇒ 臂抖。

**原样**写进 `appState.stylusOrient`，`RelayCore` **原样**读出。

**⇒ 这与"滚过 ±180 时抖"是【两个不同】的成因**（后者是接缝钳位，见上）。

### 为什么不走"把门限抬到 1° 以上"

门限作用在**偏移**上、且是**逐帧阈值** ⇒ **一旦转开 10°，偏移就是 10°，叠在上面的手抖原样通过**，
门限根本不参与。⇒ 门限只在"接近参照"那一段有用，**治不了转开之后**。

### 已实施：偏移的一阶低通（**实验之二**，回滚 = 一行）

`Config.h`：`ORIENT_STYLUS_LPF_ENABLED = true` · `ORIENT_STYLUS_LPF_TAU_S = 0.25` ·
`ORIENT_STYLUS_LPF_MAX_GAP_S = 0.5`。
`RelayCore.cpp`：对 `offx/offy/offz` 加一阶低通（**在门限之前**），
并在 `onButton2Press` 里**重置**滤波器（参照重设时必须同时重置）。

**预测**：`τ=0.25 s ⇒ fc ≈ 0.64 Hz` ⇒ 对 ~5 Hz 的手抖衰减约 **8 倍**（1° → ~0.13°，
刀尖 200 mm 处约 **0.45 mm**）⇒ 应当感觉不到了。

**⚠ 两条记账**：
1. **α 用【实测 dt】**（`dt/(τ+dt)`）—— 本项目在 `ForceCompensation::step` 上正是栽在
   "按假定采样率算 α"上（那次差 17 倍）。本函数真实调用率是 **30 Hz**（ServoP 节流）。
2. **间隔 > `MAX_GAP` ⇒ 重新对齐**，不沿用旧滤值（否则把陈旧姿态当增量补进来）。

**现场判据**：

| 完全没变化 | 说明不是这条路 ⇒ 翻回 `false`，回来重查 |
