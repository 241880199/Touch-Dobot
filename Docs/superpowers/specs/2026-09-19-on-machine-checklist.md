## 2. 采集（`'m'` 进入）

### 每个姿态

```
摆姿态 → SPACE（采样 1s）
```

### 每个【重复对】（这是模型形式检验的尺子）

```
摆姿态 → SPACE → ★【保持不动】→ 按 'r' → SPACE
```

| ★ | 规矩 | 违反了会怎样 |
|---|---|---|
| 1 | 同一对**两次采样之间机械臂不许移动** | 这一对量到的就是**两个姿态之间的重力差**（零点几 N），尺子被抬到 ~0.5 N，**门限随之放宽到几乎不判** —— 坏的正是**危险的那一侧** |
| 2 | 同一对内**不许按 `'d'`** | 柔顺状态下位姿会漂，记录的位姿与平均的力对不上（run 002 就是这么坏的） |
| 3 | **每一对换一个姿态** | 相邻两对共用一次采样 → 尺子的真实自由度只有约 2R/3，而程序按 R 报 |
| 4 | **做到 R ≥ 5 对** | 力矩分支冤枉率：**R=3 是 7~23%，R=5 才 1~5%**。停在 3 对是最坏的 |
| 5 | **姿态要"歪"** | 多来几个方向不同的**笔朝上 / 水平**极端姿态。`cond` 的实测史：**207 → 44 → 18**，逐次变好；力矩检验的**分辨力**跟着涨 |

**当场自检**：每采完一对，结算行会打出这一对的 `d` 与 `σ_rep`。
**它们该与 `'s'` 屏幕上的 `rmsF`（~0.015 N）同量级。明显偏大（零点几 N）⇒ 这一对是脏的，作废重采。**

## 5. 读机械臂自报的负载（`@1168` / `@1176`）

连接时控制台会打一行 `[Relay] 机械臂实际负载 (**【首个合格帧】的快照**): load=… center=(…)`；
**`calib_report.md` 的块尾也会带上**。

```
load = 0.404 kg    center = (0.3, -0.1, 68.7) mm      ← 首个合格帧读到的那一份
```

⚠ **两处现在会不一样，那是设计，不是故障。** 控制台那行是**首个合格帧的定格快照**（只打一次）；
而报告块、候选屏、以及下一次 `'s'` 取的是**每帧刷新**的字段（Task 8a 改的）。
⇒ **发送成功之后，两处的数必然不同** —— 那是"**快照 vs 当前**"，**不是"发送没生效"**。
**要判"发送有没有生效"，看报告块 / 候选屏那一组（实时值），别看控制台那行。**

**这两处要一起看**：

| 量 | 含义 |
|---|---|
| 机械臂的 `load` | 挂在它法兰上的**全部**（转接法兰 + 传感器 + 工具链） |
| 标定的 `m` | **测量原点以下**那部分 |

⇒ 机械臂的 `load` 应当**大于**标定的 `m`。而实测是 `0.404 < 0.4187`，**方向反了** ⇒
**机械臂存的那个 `load` 大概率偏小**。记下来，别急着改。

## 6. 发送（Task 8a/8a-2 —— **门槛已满足：Task 6 与 Task 8 均已落地**）

> **现行构建的实际按键路径（Task 8a）**：发送键 `'p'` 只摆出安全规程与**这一次要发的命令**，
> **再按 `'y'` 才真正发出**（按任何其他键取消，且取消不发出任何字节）；本版代码发**两条**
> （`EnableRobot(m,cx,cy,cz)` + `LoadSwitch(1)`），**不发 `PayLoad`**（惯量等 Task 8c）。
>
> **【两次按键，不是一次】**：`'p'` 那一下**什么都不发**。动机械臂的是**第二下**（`'y'`），
> 所以 §1 的三条（安全姿态 / 手离开工作空间 / 急停在手边）在**按 `'y'` 的时候**也仍然要成立。
> 确认之后控制台会**逐条**打两条命令的回执 —— 两条都成功才算发全。

设计 §6b 的原始清单是三条**一起**发，缺一不可（**现行构建只发其中的两条**，见上面那条注）：

```
EnableRobot(m, cx, cy, cz)      质量 + 质心（唯一通道）
PayLoad(m, I)      (= LoadSet)  惯量
LoadSwitch(1)                   打开负载设置（现行构建发的就是这一条，见上注）
```

### 发送前必须过的两道闸（都不需要额外测量）

#### 闸 1：`d = cz_robot − c_s` 必须落在 `(0, 31.5) mm`（测量原点必须在传感器体内）

⚠ **这一条要按【两种符号约定】各算一次** —— 因为 **`c_s` 沿工具轴的符号不由数据决定**
（模型在 `g → −g, A → −A, c_s → −c_s` 下不变）。实测数字：

```
d = 68.700 − 55.556 =  13.144 mm    → 在范围内  ✓
d = 68.700 + 55.556 = 124.256 mm    → 超出范围  ✗
```

**这不是学术问题** —— 它决定的正是**要发给机械臂的 `cz` 的符号**。所以：

| 情况 | 结论 |
|---|---|
| **恰好一个**落在 `(0, 31.5)` 内 | **那就是正确的符号约定** —— 按它给 `cz` 定号，可以往下走 |
| **两个都**落在内 | 数据定不了符号，**需要别的论据**；不许二选一猜 |
| **两个都**不在内 | 哪里错了，**不得下发** |

（`calib_report.md` 块尾会把**两种约定的 `d` 都打出来，且全篇不给任何 ✓/✗** ——
所以**没有"那个带 ✓ 的"可抄**，只能把两个数摆在一起，按上面那张表判。）

#### 闸 2：量级检查

`m` 在 0.2~1.5 kg、`|c| < 500 mm`。不合理就不发。

### ★ 发送之后：**这一步的产出是"读闸门"，不是"发完了"**

```
按 'p' → 看屏 → 按 'y' → 【等 3 秒】(闸门 EMA 时间常数) → 读 GuardState
                                                    → 读 @1168/@1176（实时值）与下发值对账
```

| 结果 | 含义 |
|---|---|
| **`GuardState::OK`** | 放行 ⇒ 进 §7（Task 10 闭环） |
| **仍 `INCONSISTENT`** | **不是失败，这正是要测的那个结果** ⇒ 就地量 **`\|Δc×F\|`** |

⚠ **`|Δc×F|` 是个【阻塞未知量】**：未量，估计 **≤ 0.0438 ~ 0.058 N·m**，而 `tol_M = 0.03`
⇒ **若为真，力矩通道会永远拒绝、闭环走不成**。修法有三条（绕共同点比较力矩 / 只让力通道投票 /
最保守：暂缓下发）—— **要先有数才谈得上选**。
⚠ 闸门是 **fail-closed**：它**会挡住**而不是误导。**"被挡住"本身就是结果。**

### ★ 上机前必须知道的三件事（都是 2026-09-20 才查清的）

**① 闸 2 抓不住一个【已知有界】的换帧错误 ⇒ 该预期"补偿不足"，不是"干净的无变化"。**
标定解出的 `m` 是"**传感器测量原点以下**"那一段的质量，而 `EnableRobot` 要的是"**法兰上的整条链**"。
Task 9 只为 **Z 分量**解决了换帧（`cz = d + c_s`），**质量没有对应的 `d`**。

**② 闸 1 抓不出 `cz` 的【值】错。** 本轮的 `cz` 取自 `@1176`（机械臂自报），而闸 1 又拿同一个

## 9. 留档：带走哪几个文件

⚠ **`'p'` / `'y'` 那次发送【不写进任何文件】—— 只走 stdout。** 而 `'s'` 的整屏诊断会落进
`calib/report.md`。

### ⚠ ⛔ 别用「重定向到文件」去补这个缺口（2026-09-20 试过，已退回）

当天试过 `Touch_Client.exe > send_transcript.txt 2>&1`，**失败**，两条独立的原因：

1. **cmd 没有 `tee`。** stdout 一进文件就从屏幕上消失 ⇒ **打字和读数被拆到两个窗口**。
   而客户端是用 `_kbhit()` / `_getch()` 读**控制台**的 ⇒ **能接受按键的那个窗口恰恰是
   什么都没显示的那个**，与人的直觉正好相反。当天操作员就卡死在这里。
2. **stdout 接进文件或管道会被 CRT 全缓冲。** 每对的结算行是 `printf` 打的、**从不冲刷**，
   它会**卡在缓冲里**，而不是出现在操作员正看着的地方。在控制台上 stdout 是行缓冲，一切实时。

而且**这条路根本补不上这个缺口**：发送走 `std::cout` ⇒ 就在 stdout 上 ⇒ 而 stdout 恰恰是
「既要显示又要落盘」做不到的那一路。**真正的修法是让程序自己把发送那一步写进一个文件**，
不是在外面绕重定向。**（未做 —— 记为待办。）**

（附带记录：**PowerShell 的 `>` 更不能用** —— PS 5.1 的 `>` 底层是 `Out-File`，写出来是
**UTF-16LE**（每个 ASCII 字节间夹一个 `00`），还会把原生命令的 stderr 包成
`NativeCommandError` 记录。当天那份记录**不可读**。）

⇒ **现行做法：不重定向，一个窗口。** 发送那一段暂时只能靠屏幕。
