## 2. 今天最大的悬念：残差是噪声还是系统性？

```
拟合残差                     rmsF = 0.01875 N
尺子① 姿态内噪声（窗口内）        →  χ²/dof = 5.647    ✗ 若用它则拒绝
尺子② 姿态间复现性（3 对）        →  χ²/dof = 1.49     ✓ 门限 4.135, 通过
```

**残差正好落在两把尺子之间** —— 它**超出了"窗口内平均"能解释的水平，却被"姿态间复现性"解释掉了**。

**由此确认两件事（此前都只是推断）:**

1. **"姿态内噪声是错的尺子"在真实硬件上得到证实** —— 这正是 Task 1 第二轮评审的结论。
2. **回答"要不要每个姿态多采几次": 不用。** 限制因素**不是窗口内平均**（那个已经够了），
   而是**姿态间复现性**（`0.0233 > 0.0188`）。**在同一个姿态上采更多次只会让均值更准,
   不会降低那个残差** —— 它来自"两次把臂摆到同一位置的差异", 不是采样。

## 5. 下一次采集要改的

**`cond` 206.7 与 `isotropy` 1.122 都指向同一件事: 姿态的【朝向跨度】不够。**

9 个姿态反而比上次 7 个的条件数更差 —— 说明这批姿态在朝向分布上更集中。
**下一轮要摆得更"歪": 尤其多来几个方向不同的"笔朝上/水平"极端姿态。**

## 6. 本次【什么也没应用】

不写本地补偿（`setMassCom`）、不写 `payload_calib.json` / `force_calib.json`、
不发 `EnableRobot` / `PayLoad` / `LoadSwitch`。

**原因:** 上面全部是**传感器测量原点以下**的量 —— 描述的是传感器内部质量分布 + 笔夹 + 笔，
而机械臂的负载模型描述的是**挂在它法兰上的整条链**。
两者原点不同, 换算要走过"`c_s` 的原点在哪 + 法兰→测量系那一步", **这一步未定**
（设计 §6b 末: 标定 `c_s = 54.55 mm` 与解析几何反推的 `75.8 mm` 对不上, 而传感器总高只有 `31.5 mm`）。

**下发路径的开通条件在计划 Task 9。在那之前这一屏就是全部产出。**
