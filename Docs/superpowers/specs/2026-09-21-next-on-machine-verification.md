### ★★ 1. `'z'` 调零暴露了【牛级的模型/零偏不符】—— 目前最可能的手感主因

`'z'`（20:27 存盘）之后读 `calib/force_calib.json`：

```
a_matrix     : 与 17:53 解出的【逐字相同】 ⇒ 模型没坏 ✓
com_sensor_m : 也逐字相同 ✓
bias_force_n : [-18.1802,-1.9081,+0.7457] → [-20.4728,-3.70475,+4.0782]
               ⇒ 改了 (-2.29,-1.80,+3.33), 模长 ≈ 4.5 N
```

**⇒ "多姿态拟合出的零偏"与"机械臂此刻的实际零点"差了牛级。**
**⇒ `'z'` 只是把这个误差从"处处偏"挪成"在调零那个姿态上恰好为 0"** —— 别的姿态照样偏。
**⇒ 同源证据**：静止时 `FY ≈ −0.3 N`（增益 1:1 之后手上常驻约 0.3 N），而漂移检查报 `0.569 N`。
**⇒ 这是【模型】问题不是零偏问题** —— 本项目记过的那条："残差小不能证明参数对，最小二乘把
表达不了的部分摊到其他自由参数上"。**增益 82.5× 的旧比例把它压到感觉不到；现在 1:1 它就显形了。**

**⇒ 待办**：`'z'` 之后在**几个不同姿态**上各读一次 `comp` —— 若只有调零那个姿态是 0、别处又偏，
就坐实"模型问题"（那时该走 `'m'` 采多姿态 + `'s'` 重标，而不是再调零）。

### ★★ 2. "运动时的阻力"（**无接触**也出现）—— 惯量项没补干净

现场：阻力只在**运动**时出现，且**没有接触任何物体** ⇒ 那是**工具自身惯性力**在 `comp` 里
没被 `Fi` 抵掉。根因很可能是**加速度的来源**：

```
Fi = mass × acc,  mass = 0.4196 kg
而 acc 由【100 ms 的姿态】数值二阶差分得到  ← dt 已按实测改对, 但【源头是 100 ms 的阶梯信号】
⇒ 加速度本身不可靠 ⇒ Fi 补不准 ⇒ 运动时漏出一股"阻力" ⇒ 增益 1:1 就被手感觉到
```

**⇒ 方向：把加速度来源换成机械臂 125 Hz 遥测** —— 30004 帧有 **`TCPSpeedActual` @672**，
而 `fd.tcpSpeedActual` **已经在解析**，对它差分可得到好一个量级的加速度。
**⚠ 前提**：代码注释写着 @624/@672 的**坐标系未确认** ⇒ 用之前先确认它在不在我们要的系里。

### ★ 3. 按钮2 大幅晃动 —— 待一行诊断确认（`c071456` 已加）

## A. 两处改动本身的验证（约 3 分钟，不需要写字）

### A1 控制台必须出现"触觉安全提示已关闭"横幅

**预测**：启动后控制台出现一段 `####` 框的横幅（逐条列出失能的四路），**且每 60 秒复报一次**。

**若没有** ⇒ 警告机制本身坏了（那是"代价没兑现"）⇒ 带原始输出回来。

### A2 手感里【不应该】再有排斥

**做法**：按住按钮 1，把笔尖**移向**原来会触发排斥的位置（靠近 `SAFE_Z_MAX=500`，即把笔抬高到 z≈470~490；以及靠近机械臂自身的奇异区）。

**预测**：**全程没有任何"被推开"的力**。只应感到传感器力（≈0，因为笔尖悬空）。

**带回来**：有没有推力感；若有，**在哪个位置、往哪个方向**（那说明关掉的那几路不是元凶，要另找）。

### A3 增益 1:1 的手感

**最客观的做法**：挂**已知质量**（哪怕只是"一个 190g 的东西"这种量级），按住按钮 1 轻托住，
**比较手上托的力与物体重量**（≈1:1 就是对了）。

**预测**：手上托的力**大致等于**物体的重量（1.86 N @190g）。改前只有它的 1/12。

**⚠ 两个已知的副作用，看到不要当成故障**：
- **抖动**：噪声 sd 0.11~0.16 N 会变成手上约 0.15 N 的抖动。**那是传感器底噪，不是 bug。**
  （SNR ≈2~5 是**器件决定的上限** —— 见 run-005 §7.7。）
- 若**闸门**在这时拒绝（`comp − @720` 超 1.2464 N）⇒ `compensated` 全置零 ⇒ **触觉瞬间断一下**。
  那是 **②**（参考量问题），**不是本次改动的回归**。

## C. 可选：漂移率的【长区间】测量（30~60 分钟，不占人）

**为什么**：`τ = 600 s` 是根据 `0.16 N/小时` 定的，而那个数**是从一个数据点推的**。
**⚠ 头 10~20 分钟不能用**：那段时间 `bF` 在吸收"它自己看到的姿态残差"，不是漂移（run-005 §7.5 末）。

**做法**：别碰机械臂，`m` 模式 → `SPACE` 记一次 `bF` → 隔 30~60 分钟再记一次。

**判读（我离线算）**：`ΔbF / 时长` = 真实漂移率 ⇒ 据它复核 `τ` 该不该调。
