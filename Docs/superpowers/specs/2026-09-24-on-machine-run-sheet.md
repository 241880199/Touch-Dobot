## 2. 阶段 B —— 启动那 30 行（零动作，读 ③ 的基线）

客户端连上后约 2 秒，`_tail_log` 窗口会连续出现 30 行：

```
[Force] 运动检测 #01: pos=(...)mm  tcp=(...)mm  vel=...  acc=...  tcpV=(...)  isStill=1  posR=(rx,ry,rz)  tcpR=(rx,ry,rz)
```

**看每一行末尾两组三个数**：

- `posR=` = `GetPose()` 的姿态（~10 Hz 的仪表盘查询）
- `tcpR=` = 同一帧 30004 里的 `ToolVectorActual @624`

**判据**：同一个 `#NN` 行里，两组**逐位相等（±0.05°）**
⇒ 约定相同，③ 的修法就是"把重力项的输入换成 @624"；
**不等** ⇒ 把两边的差抄回来，据此写显式转换（别猜）。

⚠ **陷阱**：若当时**三个角里只有一个非零**（例如 `(0.000, 0.000, -173.25)`），这一行**不算数** —— 不同约定在单角姿态下会**巧合相等**。这种情况不用管，阶段 C 转腕时会自动补上（探针在姿态转过 ≥5° 时继续打，最多 200 行、每行至少间隔 0.5 s ⇒ 约 100 秒的扫描额度）。

**顺手扫一眼（异常才记）**：`####` 横幅有没有出 · `一致性闸门: 放行` · `零偏漂移检查: … 正常 (< 0.5 N)`。这三项已多次确认，**不用专门测**。

### C1. 动作脚本（**一次只动一根笔杆轴**）

每个动作：按住按钮2 → 慢慢做 → **中途停 1 秒** → 反方向做一遍 → **回到按下时的姿态** → 松开。

| 顺序 | 动作 | 怎么做 |
|---|---|---|
| 1 | **前后摆** | 笔尖慢慢地**向前**摆到底（别甩）→ 停 → 回中 → **向后**摆 → 停 → 回中 |
| 2 | **左右摆** | 笔尖慢慢地**向左**摆 → 停 → 回中 → **向右**摆 → 停 → 回中 |
| 3 | **自转** | 笔杆**顺时针拧**（从笔尖看）→ 停 → 回中 → **逆时针**拧 → 停 → 回中 |

- ⚠ **不要平移**（平移不参与映射，但会混进判读）。
- ⚠ **别大甩**：限幅是 `3°/帧`，而这个上限**按"连续丢失的帧数"是无界的** ⇒ 丢包时追赶步是 `k×3°`（比 90°/s 更陡）。
