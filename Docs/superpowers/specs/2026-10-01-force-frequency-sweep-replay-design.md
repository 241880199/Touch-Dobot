# 力-频率扫描：受控回放（设计）

> **日期**：2026-10-01
> **状态**：待用户审阅
> **上游**：`Docs/superpowers/evidence/2026-09-29-on-machine-session.md` §10.4（判据先写死在那里）

---

## 1. 为什么要它

### 1.1 目标问题

悬空时手上那股 **~0.1 N**（1–3 Hz）是抖动**唯一还开着的门**。09-29 写死的判据是：
把力的波动**归一化成"单位加速度的力"**后对频率作图 ——
**基本恒定 ⇒ 惯性 · 随频率下降 ⇒ 结构性振动 · 与频率无关 ⇒ 噪声源**。

### 1.2 2026-10-01 上机拿到了什么

手摆了两轮（慢/中/快），臂确实跟上的 5 块（臂频 **0.23 → 1.37 Hz**）做二变量最小二乘：

```
F = 0.0689 · A^(−0.18) · f^(0.80)          (A = 臂运动幅度, f = 臂运动主频)
```

| 指数 | 点估计 | bootstrap 95% 区间 | 纯惯性要求 |
|---|---|---|---|
| q（频率） | 0.80 | **[−5.65, 1.31]** | **2** |
| p（幅度） | −0.18 | **[−12.78, 1.09]** | **1** |

**A 与 f 的相关系数 r = −0.833**（摆得越快臂幅度越小）⇒ 严重共线。

**⇒ 能说的**：纯惯性（q=2）落在区间外 ⇒ **不是纯惯性**。
**⇒ 不能说的**：机制是什么 —— 区间宽到 −5.65，已到这批数据的极限。
**⇒ 而且手摆再测也没用**：臂的带宽就在 ~1.4 Hz（实测 `dev` 到 2.68 Hz 时 `act` 只有 1.60 Hz）。

### 1.3 所以要什么

一个**可重复、幅度与频率解耦**的动作源。**动作必须已知安全**（末端装了笔夹）⇒ 用**日志里已经实际跑过**的轨迹。

---

## 2. 非目标（YAGNI）

- **不做**补偿 —— 本设计只**取证**。机制定名之前不写任何补偿项。
- **不做**姿态通道（`rx/ry/rz`）—— 转动那一支与"快速转阻力大"相关，但会过腕关节、可能撞接缝/超速 ⇒ **另开一轮**。
- **不动**死区 / 增益 / 滤波 / `FORCE_*` / 补偿模型的任何常数。
- **不建**通用的"轨迹回放器"（不读任意文件、不做多轨迹管理）—— 只要这一轮够用。

---

## 3. 做法

客户端加一个**回放叠加**：把日志里抽出来的一段**单频**轨迹，**缩到 ±8 mm**，按**倍速**叠加到当前 ServoP 目标上；**按一个键自动跑完整轮**（4 个倍速 × FF 开/关）。

### 3.1 轨迹从哪来（离线，一次性）

**取法 = (B)：从日志取一块 → 带通到它的主频 → 归一化成一个周期 → 循环。**

- 源块：**今天的 `13:29:00`（"中"那一档）** —— 主频 **0.36 Hz**，且 `tgt_x` 与 `act_x` 的 sd
  **几乎相等（28.80 vs 28.76 mm）** ⇒ 臂**跟上了**命令。
  **★ 为什么选它**：倍速 ×4 ⇒ **1.44 Hz**，**全程落在臂带宽（~1.4 Hz）之内**。
  若选更高频的源块（`13:29:10` 0.65 Hz ⇒ 4× = 2.6 Hz；`13:32:38` 1.36 Hz ⇒ 4× = 5.4 Hz），
  最后几段**臂跟不上** —— 那正是今天栽的那个跟头（`dev` 2.68 Hz 而 `act` 只 1.60 Hz），
  会原样再现。**宁可总跨度小一点（0.18–1.44 Hz），也不要混淆再现。**
  ⚠ 必须选"臂跟得上"的块：拿一块臂没跟上的去复制，复制的是**命令**而臂执行不出来，倍速后只会更糟。
- 步骤：去线性趋势 → 稳健主频 `f0` → 取**恰好一个周期** → 只保留 `f0` 分量（等价于对该周期做单点 DFT 的幅度/相位，再重建）→ 归一化到**峰值 1**。
- 结果：**128 点 × 3 轴**的单位峰值位移表，**生成成一个头文件**（`relay/SweepWaveform.h`），
  ⇒ 运行时**无文件依赖**、与 `'w'` 那次"纯加行"的加功能形状一致。

> **为什么不用 (A) 原样循环**：手摆的频谱很脏，而"主频"正是本实验最脆的一环
> —— 今天同一个量在两种估计法下差过 10 倍。**判据要有分辨力，主频就必须单义。**

> ⚠ **这一步是离线工具，不是运行时代码**：一个 `_extract_sweep_waveform.py`，输出那个头文件。
> **它的产物必须人眼核过**（周期是否闭合、峰值是否 1、是否只剩一个频率）再提交。

### 3.2 偏移加在哪

`Touch_Client/relay/RelayCore.cpp` 的 `// ===== Compute ServoP position =====` 那一段
（现为 `:1420-1422` 的 `servoCmdX/Y/Z = clamped.*`）**紧接其后**：

```cpp
servoCmdX += dx;  servoCmdY += dy;  servoCmdZ += dz;   // dx/dy/dz 来自回放
```

⇒ 偏移进入**随后所有**的安全/诊断计算，而不是绕过它们。
⚠ **但"随后有哪些检查"我还没在源码里逐条核过**（`:1425` 那道 `orientation` 检查只在 `m_transmittingOrient` 时跑；
按钮1 纯位置模式下**这一路到底还有什么闸**，`Config.h` 记着"工作空间钳位""虚拟约束力"**已被关掉**）。
**⇒ 写计划前必须回源码把这一段的检查逐条读一遍再定插点** —— 本仓为此栽过多次，不许凭印象。

### 3.3 一键跑完整轮

- **键**：`r`（与 `'n'`/`'z'`/`'w'` 同一族）。
- **调度**（每段 **10 s**，段间控制台打一行标记）：

| 段 | 倍速 | 力反馈 |
|---|---|---|
| 1–4 | 0.5× / 1× / 2× / 4× | **ON** |
| 5–8 | 0.5× / 1× / 2× / 4× | **OFF** |

- 全程 **80 s**。再按 `r` 或**松开按钮1** ⇒ 立即停。
- 段标记形如：`[Sweep] 段 3/8  speed=2.00x  ff=ON  (频≈1.30 Hz)` —— **分析时按它切段**（不必只靠 `ff` 列）。

### 3.4 力反馈怎么切

`appState.forceFeedbackEnabled` **本身就是 `std::atomic<bool>`**（`RelayCore.cpp:2827/2831` 那两处就是设它）
⇒ 客户端**直接设**即可，**不需要人在 MATLAB 点 `swFF`**。

⚠ **已知副作用**：MATLAB 的 `swFF` 勾选框会**显示成旧状态**（它不知道客户端改过）。
⇒ 跑完**在 MATLAB 里手动点回一致**，并在报告里写明这一条。

### 3.5 安全

| 条 | 内容 |
|---|---|
| S1 | ⛔ 偏移**只在按住按钮1 时**叠加（复用现有的 `appState.lastButtonState` 传输闸）—— 松手即停 |
| S2 | 再按一次 `r` ⇒ 立即停 |
| S3 | 幅度**硬上限** `SWEEP_AMPLITUDE_MM`（编译期常数，初值 8.0），运行时**再夹一道**到该常数 |
| S4 | 倍速上限 **4×**。源块 `f0 ≈ 0.36 Hz` ⇒ 4× ≈ **1.44 Hz**，**仍在臂带宽内**（这正是选 0.36 Hz 那块的理由）。⚠ 关节速度仍要复核（幅度是叠加的，±8 mm） |
| S5 | 偏移后的目标**仍走现有安全预测器**（NaN / 越界 / 奇异区照旧拒） |
| S6 | 回滚 = **一行**：`Config::SWEEP_REPLAY_ENABLED = false` |

## 4. 可测单元（纯函数）

按本仓的做法（`GainReadbackPolicy.h` / `GainReadback.h`），把两块**无状态**的逻辑抽出来，各自配用例：

1. **`relay/SweepPlan.h`** —— `sweepStateAt(double elapsedSec)`
   → `{ int segIndex; double speed; bool ffOn; double phase01; }`
   用例钉：段边界（正好 10.0 s 落在哪一段）、总时长之后、elapsed<0、倍速序列与 ff 序列。

   用例钉：`phase=0` 与 `phase=1` **闭合**、峰值恰为 1、三点线性插值的端点与中点。

## 6. 风险与它**不**能回答的

- **不能**给出补偿方案：它只把 `F(f)` 量干净。
- **不能**排除"臂跟不上导致的混淆"：4× 时臂大概仍跟不上（带宽 ~1.4 Hz）⇒ **判据只能用 `act` 实测频率**，这一点必须在报告里写死。
- ⚠ 源轨迹来自**一次手摆**，不是理论最优波形；它的价值在**可重复**，不在"最优"。
- ⚠ 客户端自己切 FF ⇒ MATLAB 显示会不符（见 §3.4）。
