## 4. 解读

### 4.1 `|Δc×F|` 定稿 —— 预言成真

操作单 §6 把它标为【阻塞未知量】：**估计 ≤0.0438 ~ 0.058 N·m，而 `tol_M = 0.03`**
⇒ "若为真，力矩通道会永远拒绝、闭环走不成"。

**定稿值（跨两个窗口可复现）：**

```
My = +0.0445 N·m    容差 0.030    超限 1.48×      （两窗口均值差 0.0001）
Mz = -0.0915 N·m    容差 0.030    超限 3.05×      （两窗口均值差 0.0003）
```

**`My` 正落在预测区间内、`Mz` 超出它 ⇒ 预言成立。** 而这个量以前**根本量不到**。

### 4.2 ⚠ 但真正可疑的是 `Fx`，不是力矩

**`Fx` 定稿 = +1.242 N**（两窗口均值差 0.0001），容差 0.5 ⇒ **超限 2.48×**。
而本次拟合残差只有 **0.0296 N** —— **差 42 倍，不是噪声。**

| 候选解释 | 能解释多少 |
|---|---|
| 质量差（`m` 0.4040 → 0.4173，+0.0133 kg）的 `Δm·g` | 约 **0.13 N** |
| **实测** | **1.24 N** —— 差近 10 倍 |

⇒ **"机械臂的 m 小了一点"解释不了 `Fx`。** 量级 ~1 N 与"**换帧差异**"相符（若整条链真如
解析几何估的 ~0.657 kg 而本地是 ~0.417 kg，差 ~0.24 kg ⇒ ~2.4 N）。**这正是 §6 ① 警告过的**：
闸 2 抓不住这个换帧错误 ⇒ 该预期"补偿不足"。

#### ⚠ 一条扎实的推论，和一条【被它自己推翻】的推论

**先给扎实的那条** —— 把原点平移 δ（朝向不变）：同一个力旋量里 **`F` 是自由矢量、不变**；
只有 `M → M + δ × F`。而模型是 `F = b_F + A·g`、`M = b_M + c_s × (A·g)` ⇒

> **平移原点【只能】把 `c_s` 变成 `c_s + δ` —— `A` 与 `b_F` 一个字节都不动。**

**⇒ 力通道的分歧【不是"原点在哪"的问题】。** 这一条成立。

**⚠ 但由此【推不出】"下发治不了力通道"** —— 写下这一节时我那样推过，错了。错在把
`comp − @576` 的两边当成了"两个模型的同口径差"。实际上：

```
comp   ≈ 0        我们这边几乎补干净了 (拟合残差 0.0296 N)
@576   ≠ 0        它是【机械臂自己】补完之后【剩下】的那一份
⇒ comp − @576 主要就是【机械臂那一半没补掉的东西】
```

而机械臂存的是 `load = 0.404 kg`，整条链按 CAD 估 **~0.657 kg**
⇒ 未补掉约 **39%**；重力负载 ~6.4 N × 39% ≈ **2.5 N** ⇒ **正是实测的 1.24 ~ 2.76 N。**

**⇒ ⟹ 闸门报的很可能就是"机械臂的负载参数偏小" —— 而那恰恰是"把正确的负载发下去"能治的。**

#### ⛔ 【2026-09-20 晚 —— 下面这两小节作废，保留原文只为对账】

它们把 `comp − @576` 当成"**我们的模型 vs 机械臂的负载模型**"的差去拟合 H1/H2。
而后来实测（§4.5）：**`@576` 是【传感器侧】的量，不是机械臂负载模型的输出** ——
所以那一整套拟合描述的是 **`@576` 自己的形状**，不是"两个模型之差"。
**"H1 被排除"这个结论因此不成立**（它排除的是一个没被真正问过的问题）。
**不要再据此下任何结论。**

#### 两个假设，量级都对得上，现在还分不开

**⚠ 因为读数没有记录姿态**（见 §3 的三条警告），下面两条暂时无法判别：

| 假设 | 预测的姿态依赖形式 | 该怎么做 |
|---|---|---|
| **H1: 机械臂 `load` 偏小**（0.404 vs 整条链 ~0.657） | 残差 ∝ `g_法兰` ⇒ 纯重力方向依赖，幅度 ~2.5 N | **把正确的负载发下去，看闸门改不改善** —— 这就是 8b 本来要测的 |
| **H2: 传感器系与法兰系差一个旋转** | 残差 ∝ `(I−Q)·g`，`Q` = **30.05°** 旋转（实测，列模长 0.989/1.017/0.996） | 在闸门里**先把 `comp` 转到法兰系再比**（`Q` 已经算出来了） |

**两者都是 ~2 N，所以靠幅度分不开。**

#### ⇒ 判别方法：**拟合出来的 `M = 残差 / g` 的【各向同性】就是分水岭**

**两个假设都预测"残差对 `g` 线性"** ⇒ 看拟合残差分不开。**但它们的 `M` 一个各向同性、
一个不是：**

| 假设 | 预测的 `M` |
|---|---|
| **H1**（`load` 偏小） | `M = (m_true − m_robot)·I` ⇒ **标量 × 单位阵（各向同性）** |
| **H2**（坐标架差一个旋转） | `M ≈ c·(I − Q)` ⇒ **强各向异性**（形状由已测的 `Q` 定） |

**做法（零成本，也最该先做）：下次读闸门时，把姿态一起抄下来**（`GetPose` 的六个量）。
攒到 **≥4 个姿态**（现在已有 4 个，但姿态没记）就能拟合 `M`，一眼看出是各向同性还是 `I−Q` 形状。

**备选的直接检验（⚠ 很弱，可能判不出来）**：按 `'p'` → `'y'` 把负载发下去看残差走不走。
但候选 `m = 0.4173` 是"**测量原点以下**"的值，而机械臂要的是**整条链**（估 ~0.66）——
这次只能补上缺口的一小部分，**残差预计只降一点点**，发了也分不清是 H1 还是没变。
**要真做这个检验，得先知道整条链的质量 —— 而那正是未定的那个量。**

### 4.4 闸 1 的下端点隐含了 `t = 0` —— 一条本已记在案、但没接上的账

**闸 1 判据是 `d ∈ (0, 31.5)`，而物理上应当是 `(t, t + 31.5)`**，`t` = **转接法兰厚度**。

上端 31.5 的来历是"测量原点必须落在传感器**体内**"，那是从**机器人法兰面**量起的。而传感器

⇒ 取下端 = 0 使判据**偏宽松**：`d ∈ (0, t)` 这一段物理上不可能，却会被判成"在范围内"。
而闸 1 的职责正是**给 `cz` 定符号** ⇒ **假通过的后果是可能定错符号**。

**`t` 在全仓库没有任何图纸或实测数据**：

### 4.5 ★★ `@720` 并排报出来之后 —— 力通道的答案是【参考量选错】

厂商接口文档把两个 TCP 力分得很清楚：

```
ActualTCPForce @576 = "TCP【传感器】力值"
TCPForce       @720 = "TCP力值 (【通过关节电流计算】)"
```

"通过关节电流算力"就**必须知道负载**（重力矩 + 惯量矩）⇒ **`@720` 才反映控制器在用的负载参数**。
**而一致性闸门比的却是 `@576`。**

**2026-09-20 晚把两组差并排报出来（闸门表每行末尾 + 复报行），在同一个姿态上连续四次：**

```
        comp−@576   comp−@720    容差       比值
Fx(N)    +2.558      +0.0435    0.500     59×  【更小】
Fy(N)    +1.473      +0.156     0.500     9.5× 【更小】
Fz(N)    +0.031      -0.073     0.500     不投票; 两者都远小于容差
Mx(Nm)   -0.096      +0.061     0.030     ≈ 同级(反号)
My(Nm)   +0.115      +1.147     0.030     10×  【更大】
Mz(Nm)   +0.061      +1.316     0.030     22×  【更大】
```

**⇒ 两半的结论相反：**

| | 结论 |
|---|---|
| **力通道** | **`@720` 比 `@576` 小 10~60 倍 ⇒ 闸门该比 `@720`。** 若换过去，力通道**会放行**（Fx 差 0.04、Fy 差 0.16，都远小于容差 0.5）|
| **力矩通道** | **反过来 —— `@720` 是 `@576` 的 10~22 倍（约 1.0~1.3 N·m，而容差只有 0.03）** ⇒ 换成 `@720` 会让力矩**拒得更狠** |

**⚠ `@720` 那个 ~1.2 N·m 的力矩不可能是质心误差**：`1.2 ÷ (load·g ≈ 4 N) ≈ 0.3 m` ——
**300 mm 的质心偏差不可能**。⇒ **它是 `@720` 自己带的**（关节电流反算的模型误差 / 摩擦 /
部分实现），与我们的模型无关，要**单独查**。

**它还带"整定"形态**：四次复报里 `My` 1.147 → 1.101 → 1.012 → 0.986、`Mz` 1.316 → 1.275 →
1.201 → 1.207 ⇒ **读数要等它稳了再抄**（与力通道那次 0.04~0.08 N 的整定同一个样）。

#### ⇒ 对"闸门一直在拒"，最终结论分两半

```
力通道    →  【参考量选错】。改成 @720 就会放行。
力矩通道  →  【两边都不对】，而且 @720 差得更远 —— 换参考量解决不了它。
```

**⇒ "换成 `@720`"不是一把钥匙。** 它治好力那一半，同时让力矩那一半拒得更狠。

#### 顺带：那条"`@576` 不跟负载配置变"的记录，现在有解释了

`@576` 是**传感器侧**的量 ⇒ 它**本来就不该**跟着 `EnableRobot` 的负载走 ✓。
那条记录一直挂在 `relay/RelayCore.cpp` 的注释里写着"**为什么还不清楚**" ——
**答案就是它的定义。**

#### ★ 补：用【已有数据】把 §7.1/§7.2 两条都查清了（当晚，不再需要现场）

**① `@720` 的力矩 = 一个【会漂】的姿态无关偏置 ⇒ 不是负载效应**

把三轮的 `@720` 力矩各拟合一次 `M·g + c`：

```
        偏移 c                     随姿态幅度 |M|          偏置占比
21:58   (+0.614, +0.492, -0.225)   (0.101, 0.059, 0.022)   86% / 89% / 91%
22:12   (+0.406, +0.047, -0.374)   (0.080, 0.027, 0.013)   84% / 64% / 97%
22:18   (+0.064, +0.020, -0.377)   (0.068, 0.083, 0.027)   48% / 19% / 93%
```

**⇒ 约 90% 是一个【与姿态无关的偏置】，而那个偏置自己在漂**
（`Mx` 的 `c`：0.614 → 0.406 → **0.064**，二十分钟漂了 **0.55 N·m**）。

**重力/负载效应的形状不是这样** —— 那必然随姿态变，且**不产生姿态无关的偏置**。
⇒ **它是 `@720` 那条通道自己的东西**（关节电流反算里的摩擦 / 零点 / 部分实现），
**与我们的模型无关，也不能当力矩通道的参考量。**

**⇒ ⇒ §7.2 那个"现场看它恒定还是随姿态变"的步骤【不用做了】—— 数据已经答了。**

**② `@576` 的重力系数在负载改动前后【纹丝不动】—— 实测复现了那条老账**

```
        该通道认为"被补偿掉的质量" |M|
@576    0.206 / 0.208 / 0.211  kg      ← 三轮(含发送前后) 纹丝不动
@720    0.007 → 0.016 (x)              ← 动了: 方向对, 幅度约一半, 1~2σ(不显著)
```

`load` 从 `0.404` 改到 `0.422`（**+0.019 kg**）之后，`@576` 的系数**一点没动** ✓
⇒ **那条"改负载 `@576` 纹丝不动"到此有了实测复现 —— 而原因就是它的定义。**

**③ ⚠ 但 `@720` 的力也有一个「在漂的偏置」—— 换参考量不是免费的**

```
@720 力:  偏移 c 在三轮里漂了 (0.144, 0.181, 0.055) N
          随姿态幅度 |M| ≈ 0.02
```

它确实比 `@576`（偏置 −1.2 ~ −2.0 N、系数 0.21）**小 10~60 倍** ✓，
**但它有一个约 0.15 N 的、会漂的偏置** ✗ ⇒ **换过去必须重标容差，并把这个漂移算进去。**
