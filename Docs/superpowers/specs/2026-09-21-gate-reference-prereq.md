## 3. Step 2 —— Task 3 要用的两个数（算式 + 输入 + 出处 + 结果）

### 3.1 计划给的算式

```
forceOffsetMax_N   = max(所有轮次里 |@720 力通道偏置|)        <- 取绝对值最大的那个
forceOffsetDrift_N = max(所有轮次) - min(所有轮次) 的幅度
```

⚠ **算式没写归约维度**：`@720` 力偏置是**三分量向量**，所以"所有轮次里"既可指"每轮先归约成一个数"
也可指"逐轴各自跨轮"。几种读法都给（下面 A/B 两组的差别就在这，§3.3 的漂移有 3 行）。

⚠ **两行的绝对值写法不对称，这决定了 `Drift` 该取哪一读（这一条是 §3.4 里 0.6722 那一行的来源）:**
- 第一行**显式带 `|·|`** ⇒ `Max` 无歧义，就是**幅值**最大值（`0.1548`）。
- 第二行**没有** `|·|`：它写的是 `max(…) − min(…)` **再**"的幅度"。
  `max − min` 的自然对象是**带符号的跨轮极差**（"漂"就是这个意思），
  `的幅度` 只是对**这个差值**取绝对值（差值本身已经是正的）。
  ⇒ **`Drift` 的自然读法是"按轴、带符号极差"**：`0.1434 / 0.1813 / 0.0915` ⇒ `0.1813`。
  **"先对每个轴取 `|c|` 再跨轮相减"（`0.1389`）是次自然的读法** —— 它要额外插进一次
  逐轴取绝对值，而那一次**算式里没有**。

两种都算出来（§3.3 三行 / §3.4 的 B 三行），因为两种都不改变结论；
但**给 Task 3 的是上界，即上面的自然读法那一行**。

## 5. 复现方法（后面任务可照此重跑，逐条给式子）

**① 重力（唯一实现，符号约定照 `TcpCalibration`）**

```
R = Rz(rz)·Ry(ry)·Rx(rx)                      (row-major)
g_f = G · (R[6], R[7], R[8])                  # G = 9.81（常量取自 TcpCalibration.cpp）；即 Rᵀ·(0,0,G)
g   = Rz(−ψ) · g_f                            # ψ = sensorYawDeg；全量模型走 AtYaw(pose, 0.0) ⇒ ψ = 0
⇒ 用 ψ=0 时:  g = 9.81 · (−sin ry,  cos ry·sin rx,  cos ry·cos rx)
```
⚠ **`psi` 对下面 §②③ 的 3 列回归没有影响**：绕 z 的旋转把 `(gx,gy)` 做一个固定的可逆线性变换，
`span{(gx,gy,gz)}` 不变 ⇒ 截距不变。（我实测过 ψ = 0/±90/45/135 结果一致。）

**② 逐通道偏置 `c`（本文 §2.2 / §2.3 用的就是它）**

```
每个分量 a ∈ {x,y,z}：   y_a(pose_i) = c_a + k_a · g(pose_i)        # 3 个回归子 (常数 + gx,gy,gz)
c_a = 截距 (最小二乘)
|M|_a = ‖k_a‖    （质量系数的幅度；量纲：力通道 = kg，力矩通道 = N·m）
```

### 7.1 两个误差项（来源不同，不是同一个量的两次估计）

### 7.3 合并规则 —— 取【相加】，并说明这是判断不是推导

```
eps_F = eps_甲 + eps_乙 = 0.2871 + 0.3361 = 0.6232 N     (未舍入 0.287098 + 0.336054 = 0.623152)
tol_F = 2 × 0.6232 = 1.2464 N                             (余量 = 1.2464 / 0.6232 = 2.00)
```

**为什么是相加（而不是平方和）—— 以及为什么这一步是【判断】:**
- 两组测量**没有给出联合分布** ⇒ "两者独立"这个前提**没有依据**；
- 两者**可能部分重叠**：机械臂那一侧的模型类残差，正好也是参考量偏置的一个**可能来源**。
  本文件**没有**判它（手上只有三轮、两个日期），所以这不能当成"已确认独立"；
- 测量的现状也**不足以**证明相加不过头：三轮 `@720` 数据上**直接量到**的
  `|compensated − 参考量|` 逐姿态最大值（只算投票的 `Fx`/`Fy`）只有 **0.1775 N**
  （三轮分别是 0.1775 / 0.1692 / 0.1741）—— 比 `0.6232` 这个**界**小 **3.5 倍**。
- ⇒ 取**保守（较大）的那一边**：相加。**代价要写下来**: 平方和给
  `√(0.2871² + 0.3361²) = 0.4420 ⇒ tol_F = 0.8840 N`；相加比它宽 **0.3624 N（1.41 倍）**，
  折算成负载质量误差是 **0.127 kg** 而不是 **0.090 kg**。

`eps_乙` 内部还自带一层**有意保守**（§3.4 已经点明）：`Max` 与 `Drift` 用到同一个采样
（21:58:46 的 `c_y`），所以 `eps_乙 = max c_y + 2·|min c_y|`。这一层**保留**，不折减。

### 7.4 最终取值 = `1.2464 N`，以及它**还能抓住什么**（用户约束的落点）

闸门在 `|EMA(compensated − 判据参考量)| > tol_F` 时拒绝 `Fx`/`Fy`（`Fz` 不投票）。

- 相对上面那个**界**的余量 = **2.00x**；相对**三轮实测到的最大合法差 0.1775 N** = **7.0x**。
- 折算成**负载质量误差**：臂侧负载与本地模型差 `Δm` 会在重力方向上产生 `Δm·9.81`，
  取最不利取向 ⇒ 门限 `Δm = 1.2464 / 9.81 = 0.127 kg`（= 工具链实测质量 0.4159 kg 的 31%）。
- **已知的那个失效模式仍被抓住**：机械臂还拿着种子负载 0.66 kg 而实测 0.4159 kg
  ⇒ `Δm = 0.244 kg` ⇒ 最不利取向下 **2.39 N > 1.2464 N**，余量 **1.92x** ⇒ 仍然**拒绝**。
- **代价**：旧 `tol_F = 0.50 N` 的门限是 `Δm = 0.051 kg` ⇒ 同一条灵敏度掉了 **2.49 倍**
  （要 2.49 倍大的质量误差才触发）。**0.90 N 量级的持续不一致过去会拒，现在不会。**
- ⚠ 上面全是**静止**口径的灵敏度（量的是"模型错多少会被拒"），**不是**"外力多少会被拒"：
  换参考量后闸门在**真实外力**下的行为**没有任何仓库文件验证过**（§4.2①，遗留风险不变）。

### 7.5 本节**不**支持的读法

- 「照抄 `0.144/0.181/0.055`」—— §3.5 不变，仍不允许。
- 「`eps_甲` 与 `eps_乙` 可以平方和合并」—— 没有依据（见 §7.3），且取小是 fail-**open** 的方向。
- 「`0.6232` 是典型值」—— 它是**界**；三轮直接量到的最大合法差比它小 3.5 倍。

## 8. Task 5 的落地（2026-09-21）—— 零偏漂移检查的判定被抽出来并逐分支覆盖

### 8.1 为什么必须动它

`runZeroDriftCheck()` 是 `main.cpp` 的 file-static，由主循环用**真实时间**驱动，
直接读 `appState.forceData` 与 `ForceCompensation::guardState()`，**没有可注入点**；它
**不写任何文件**（只有 stdout 与内存里的 static）。而它**只在闸门放行后才做事** ——
闸门此前一直拒绝，所以它至今跑的全是【未做】那一支。§7 换参考量 + 力矩不投票之后，
「放行 → 正常」与「放行 → 超阈」这两条路会**首次**在现场执行。一条从未跑过、又没有
用例的路径，不能只靠现场兜。

### 8.2 抽到哪、边界划在哪

判定抽成 `Touch_Client/force/ZeroDriftCheck.h` 里的**头文件内联纯函数**
（`ZeroDriftCheck::decide`）：不吃时钟、不读全局、不打印。输入 = 闸门状态、三轴**均值**、
从**第一次被拒**起算的时长、样本数、阈值、等待期、最少样本数；输出 = 结论
（正常 / 超阈 / 未做 / 样本不足 / 等待中）+ 该说的话。时间与全部 module-static 累计量留在
`main.cpp` 的调用侧。

**为什么选头文件内联（而不是单独 `.cpp`）**：单测的构建脚本是 `cl` + **显式源文件列表**，
而项目构建走 MSBuild —— 单独 `.cpp` 要同时改**两处**，漏一处就是"单测编得过、真机构建链接
不上"（或反过来）。内联头文件没有这个二义性，且两边编译的是**同一份定义**，用例调的
就是真实实现。

### 8.3 五支覆盖 + 两条边界

| 分支 | 用例钉住的东西 |
|---|---|
| 放行 → 正常 | 结论**不是**「未做」；报的数是它自己算的三轴模（与任一分量都不同），且文字里出现的就是那个数 |
| 放行 → 超阈 | 同上，且阈值也写进话里。用的例子是 **0.8 N 静偏**：闸门容差 `1.2464 N` 之内 ⇒ 闸门放行、本检查照报 |
| 拒绝满等待期 → 未做 | 闸门的**三种**拒绝原因**都走这一支**（`UNCALIBRATED` / `INCONSISTENT` / `REFERENCE_UNAVAILABLE` —— 第三种是 Task 7 加的，见 §9.5）；话里**不许**出现「补偿后读数」（拒绝期间那个数恒为 0，不是零偏）；等待秒数要报出来 |
| 等待中（差 1 ms） | 结论是「等待中」而**不是**未做，且**一个字都不打**（旧行为，保持不变） |
| **样本不足** | ★ 必须出声（见 8.4）；不许出现「补偿后读数」；样本数与下限都要报出来 |
| 边界：恰好等于阈值 | **不报** —— 判据是**严格大于**，与抽出前逐字一致（取 0.5 N 单轴，`sqrt(0.5²)` 在二进制里精确，不是浮点碰运气） |
| 边界：样本数 9 与 10 | 9 ⇒ 样本不足；10 ⇒ 必须给结论 |

### 8.4 修掉的那条静默路径（用户指令）

也不报"没查"，于是**"查了、没发现问题"与"根本没查"在输出上分不开**，与该文件自己写的
原则（「『没查』必须有句话」）冲突。现在明说：

```
[Force] 零偏漂移检查: 【样本不足】—— 闸门放行后只累计到 N 个样本 (至少需要 M 个),
        样本不足, 本次不作结论。
```

已与夹具重采同批延后。所以本任务的交付是**"可单测 + 逐分支有覆盖"**，**不是**"这条路径已在
实机跑通"。上面那张表里"放行 → 正常 / 超阈"两行，验证的是**判定**；**"闸门在真机上第一次
放行之后，采到的样本数与读数真能走进这两支"这件事，仍然一条现场记录都没有。**
硬件工作恢复后按本文 §5 的口径补记，并写进本文件。

另注：`0.5 N`（本检查）与 `1.2464 N`（闸门容差）**不要对齐**。本检查比闸门**紧**是设计，
不是不一致 —— 闸门管的是"模型对不对得上"，本检查管的是"零偏漂到哪了"。

## 9. Task 7 的落地（2026-09-21）—— 参考量"不可用"时 fail-closed

### 9.1 为什么要有这一条

闸门的判据是 `compensated − 参考量`。**参考量读到 ~0 时**，判据退化成"本地输出是否在自己的
容差内" —— 而按构造它总是在。于是闸门会**在一个不携带信息的通道上放行**。"零"既可能是
"真的没有外力"，也可能是"这一路没有数据 / 已失效"，**两者从前不可区分** ⇒ 对"没有信息"
放行就是 fail-open。用户 2026-09-21 指令：加存在性守卫，**不可用时不放行**；
约束是**"安全起见不符合时还是要拒绝"**。

### 9.2 ⚠ 性质：这是【防紧】，**不是修一个正在发生的 bug**

生产链路上 `RelayCore` 在**同一次 30004 收帧、同一把 `forceDataMutex`** 里一起填
`raw[]` / `tcpForce[]` / `sixForceRaw[]` / `sixForceOnline` ⇒ **"通道其实有数但读数为零"
在实机目前不可达**。它只在**回放 / 夹具**路径出现（`tests/fixtures` 的四份采集**没有参考量
那一路的列** ⇒ 判据那一侧恒为 0）。**不许把本任务写成"修了一个活 bug"。**

### 9.3 判据：两个**既有**信号，**没有新门限**

| 信号 | 它是什么 | 为什么够用 |
|---|---|---|
| `fd.sixForceOnline` | 30004 帧 `@1037` 六维力在线状态。实机实测值 = **1**（四份夹具文件头记的 `sixForceOnline=1`）；`ForceData` 初值 `−1` = **一帧都还没收到** | **只有 `== 1` 才算"这一路在线"**。取"正向确认"而不是"没说不在线就算在线"：无法确认时**不放行**才是 fail-closed；而实机实测值就是 1 ⇒ 不会把正常工况判成不可用 |
| `fd.isStale` | 既有超时常量 `Config::FORCE_STALE_MS` 的落点（`RelayCore::pollForce` 用 `lastUpdateMs` 与它算出这个标志，**就在 `step()` 之前、同一把锁内**） | 陈旧帧里的参考量是**上一次读数**，不是这一路的当前状态 ⇒ 同样不可用。**读这个标志而不是自己再算帧龄**：帧龄算法只有一份，库里再算一份就会出现"闸门说新鲜、F| 组帧说陈旧"两个答案 |

⇒ 两者都是**布尔 / 枚举级的事实**，**不需要任何新的数值门限**。这也是本判据**不许**凭感觉
取一个"零附近多大算零"的原因：那种门限会把**"真的没有外力"**判成不可用。
判据的唯一一份实现：`ForceCompensation.cpp` 的 `guardReferenceAvailable`。

### 9.4 "不可用"与"不一致"**必须分得开**（用户已否掉"把未验证的东西变绿"）

新状态 `GuardState::REFERENCE_UNAVAILABLE`（第 4 个值）+ 新错误码
`ERR_FORCE_REFERENCE_UNAVAILABLE`（**不复用** `ERR_FORCE_INCONSISTENT`：那个码的字面意思是
"两边都读到了数、但对不上"，而这里**没有比过** —— 报成"对不上"会让日志里出现一个没发生过
的事实，操作员照它去查下发会白忙）。`ERROR_CODE_SLOTS` 25 → 26（与 `RobotError.h` 顶部的
计数注释同步）。

`test_payload_calibration` 的 `runtime_consistency_guard_replay` 那条**红线断言**：
- **改动前**：夹具缺参考量列 ⇒ 参考量恒 0 ⇒ 判据退化 ⇒ **放行** ⇒ 断言失败，消息"竟然放行了
  (state=OK)"（基线 **69 passed / 1 failed**）。
- **改动后**：同一份夹具被判成**参考量不可用**、同样拒绝 ⇒ 断言**同样不成立**，
  消息改为"不是 INCONSISTENT (state=REFERENCE_UNAVAILABLE)"，并**明写它仍然没有验证过
  新参考量**。计数**仍是 1 failed**（**69 passed / 1 failed**）。
- ⇒ **那条 0 不代表原断言通过**：它问的是"两边**比过**之后会不会拒绝"，而这里两边
  **没有比过**。记成通过就是把一件未验证的事变绿 —— 用户明确否决过。
