## 3. Step 2 —— Task 3 要用的两个数（算式 + 输入 + 出处 + 结果）

### 3.1 计划给的算式

```
forceOffsetMax_N   = max(所有轮次里 |@720 力通道偏置|)        <- 取绝对值最大的那个
forceOffsetDrift_N = max(所有轮次) - min(所有轮次) 的幅度
```

⚠ **算式没写归约维度**：`@720` 力偏置是**三分量向量**，所以"所有轮次里"既可指"每轮先归约成一个数"
也可指"逐轴各自跨轮"。两种读法都给（下面 A/B 两组的差别就在这）。

### 3.2 输入 A —— 记录值（**无文件支撑、且不可复现，§2.2**）

输入：`0.144` / `0.181` / `0.055`（出处 `run-004 §4.5③`）

```
forceOffsetMax_N   = max(0.144, 0.181, 0.055) = 0.181 N
forceOffsetDrift_N = 0.181 − 0.055            = 0.126 N
```

### 3.3 输入 B —— **可复现值**（本文件 §5 方法算出，可重跑）

输入（§2.2 表）：逐轮 `max_axis |c|` = `0.1548` / `0.0418` / `0.0756` N

```
forceOffsetMax_N = max(0.1548, 0.0418, 0.0756) = 0.1548 N
   ← 最坏观测值 = 21:58:46 轮的 y 分量 c_y = −0.154790 N（取绝对值）
```

漂移，两种归约都算：

```
按轮归约:  forceOffsetDrift_N = 0.1548 − 0.0418 = 0.1130 N
按轴归约:  x 轴 0.0756−0.0382 = 0.0374
           y 轴 0.1548−0.0159 = 0.1389     <- 三轴最大
           z 轴 0.0497−0.0209 = 0.0288
           ⇒ forceOffsetDrift_N = max(0.0374, 0.1389, 0.0288) = 0.1389 N
```

### 3.4 ★ 关键：**用哪组输入都不改变 Task 3 的结论**

Task 3 的判据是 `余量 = FORCE_GUARD_TOL_FORCE_N / (Max + Drift) ≥ 2`：

| 输入 | `Max` (N) | `Drift` (N) | 最坏 `Max+Drift` (N) | 需 `tol ≥ 2×最坏` (N) | 现行 0.50 的余量 |
|---|---|---|---|---|---|
| **A** 记录（无文件） | 0.181 | 0.126 | 0.307 | 0.614 | 1.63 ❌ |
| **B** 按轮归约（可复现） | 0.1548 | 0.1130 | 0.2678 | 0.5356 | 1.87 ❌ |
| **B** 按轴归约（可复现） | 0.1548 | 0.1389 | 0.2937 | 0.5874 | 1.70 ❌ |

**⇒ 三种读法全部 < 2 ⇒ Task 3 无论如何都要把 `FORCE_GUARD_TOL_FORCE_N` 上调**（现行 0.50 不够）。
**这个结论对"用 A 还是用 B""用哪种归约"都不敏感** ⇒ 本复核**没有挡住 Task 3**。

**⇒ 给 Task 3 的具体指示:** 用 **B 组**（唯一有文件支撑的输入），归约取**上界**：
`Max = 0.1548`、`Drift = 0.1389` ⇒ 最坏 `0.2937` ⇒ **`tol ≥ 0.5874 N`**。
⚠ 并且要在 `Config.h` 注释里写明**用的是哪种归约** —— 算式本身没定义它（§3.1）。

⚠ **另一条要写进注释的:** `Max + Drift` 把同一个量算了两次（`Drift` 的一个端点就是 `Max`，
即 `Max + Drift = 2×max − min`）。这是**偏保守**的，不是错误，但**必须写成"有意保守"**，
否则下一个人会以为它算错了。

### 3.5 这两个数**不支持**的用法

- 「用 `0.144/0.181/0.055` 反推 `@720` 别的性质」—— 没有文件，不要用。
- 「`@720` 力矩的 `c` 也可以这样取一个上界」—— 力矩的 `c` **有文件**（§2.3），
  但计划**不让力矩投票**（Task 4），所以力矩那两个数**不进 Task 3 的算式**。

- 若 `@720` 对外力的**符号与我们相反**，静止时的一致会**把这个完全掩盖**：
  真出现外力时，闸门看到的将是**约 2 倍的偏差**而不是 0。
- 仓库里**没有任何文件**（接口文档 markdown 只给了"通过关节电流计算"一句，

  不是"外力下验过"。**
- ⚠ 检验它需要真加一个外力 / 动机械臂 —— **那不在本计划的范围内**。
  ⇒ 这条**留着**，是本计划的**主要遗留风险**。

**② 零信息量风险的一般形式。** `@720` 的力**已经被机械臂自己补偿掉了**：它的质量系数只有
`0.007 ~ 0.016 kg`，而实际工具链质量是 **0.4159 kg**（= 已安装模型的 `massScaleOf(A) = |det A|^(1/3)`，
`A` 取自 `force_calib.json`；与 `calib_log.txt` 的 `mass_kg` 列在 `22:18:42` 记录的 `0.415864` 一致）。
⇒ 静止时"我们 vs 它"比的是**两个都≈0 的残余**。这与①是同一件事的两面。

**③ 支撑"换"的数字里有一个是坏的。** `run-004 §4.5③` 的 `@720` 力偏置三元组
**无文件且不可复现**（§2.2）。⇒ 不能排除同段的其它 `@720` 说法也有同样的来源问题。
（已核：§4.5① 的力矩表与 §4.5③ 的 `@576` 对照值**都复现了**，所以坏的是**那一个三元组**，
不是整段。）

**④ 换过去力矩拒得更狠（复现）。** 计划已用"力矩不投票"（Task 4）处置，但那是**绕过**、
不是**修**：力矩通道**仍然没有可用参考量**（`@576` 差 0.1 且不跟负载；`@720` 差 ≥ 0.2 且带会漂的偏置）。

**⑤ 容差不是免费的。** §3.4 表明 `tol` 必须上调。**上调后它还能抓住什么必须写下来**，
否则就是"宽到抓不住任何东西的容差"（用户约束原话："门限可以适当降低标准，
但安全起见不符合时还是要拒绝"）。

**不推翻"换 `@720`"。** 理由：决定这条的三件事 ——（a）两个通道的定义（有文件）、
（b）`@720` 才与我们的补偿量一致（我复现）、（c）`@576` 不跟负载走（我复现）—— 都在文件里站得住。
**Task 2–6 可以继续。**

**但必须连同下面三条一起执行，否则这个判决是"看起来成立"：**

## 5. 复现方法（后面任务可照此重跑，逐条给式子）

**① 重力（唯一实现，符号约定照 `TcpCalibration`）**

```
R = Rz(rz)·Ry(ry)·Rx(rx)                      (row-major)
g_f = G · (R[6], R[7], R[8])                  # G = 9.81（常量取自 TcpCalibration.cpp）；即 Rᵀ·(0,0,G)
g   = Rz(−ψ) · g_f                            # ψ = sensorYawDeg；全量模型走 AtYaw(pose, 0.0) ⇒ ψ = 0
⇒ 用 ψ=0 时:  g = 9.81 · (−sin ry,  cos ry·sin rx,  cos ry·cos rx)
```
⚠ **`psi` 对下面 §②③ 的 3 列回归没有影响**：绕 z 的旋转把 `(gx,gy)` 做一个固定的可逆线性变换，
`span{(gx,gy,gz)}` 不变 ⇒ 截距不变。（我实测过 ψ = 0/±90/45/135 结果一致。）

**② 逐通道偏置 `c`（本文 §2.2 / §2.3 用的就是它）**

```
每个分量 a ∈ {x,y,z}：   y_a(pose_i) = c_a + k_a · g(pose_i)        # 3 个回归子 (常数 + gx,gy,gz)
c_a = 截距 (最小二乘)
|M|_a = ‖k_a‖    （质量系数的幅度；量纲：力通道 = kg，力矩通道 = N·m）
```

**③ 校准（证明 ② 的口径没错，这三条必须同时成立）**

| 校准对象 | 记录值（出处） | 我的重算 | 结果 |
|---|---|---|---|
| `@720` 力矩 `c`，三轮 × 三分量 | `run-004 §4.5①` | 逐位相同（§2.3） | ✅ |
| `@576` 质量系数（x 分量），三轮 | `run-004 §4.5②` 的 `0.206 / 0.208 / 0.211 kg` | `0.2059 / 0.2076 / 0.2113` | ✅ |
| `@720` 质量系数（x 分量），后两轮 | `run-004 §4.5②` 的 `0.007 → 0.016` | `0.0075 → 0.0164` | ✅ |

⇒ 口径钉死。**在这个口径下 `@720` 力的 `c` 得 §2.2 表，而它给不出 `0.144/0.181/0.055`。**

**④ 闸门对比的复现（§2.1）**

```
comp[0..2] = @1304[0..2] − bF − A·g
comp[3..5] = @1304[3..5] − bM − (c_s × (A·g))          # 静止 ⇒ 无惯性项
记录量:  comp − @576 ,  comp − @720
A, bF, bM, c_s 取自 Touch_Client/calib/force_calib.json
```
⚠ 该 `json` 是 **22:18:42 INSTALLED** 那一版；用它去算更早的两轮会带一点模型差
（这正是 §2.1 里三轮均值不同的来源之一）。**三条结论对这一点不敏感**（三轮都同向）。
