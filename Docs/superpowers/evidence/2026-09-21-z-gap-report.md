## 0. 判决（先给结论）

**判决：三种允许的结论里的第 1 支。**

> **「38~64 N」不是 z 上的任何实测差，它是 `tol_M / |c_s_横向|` —— 力矩通道"能看见多大的 ΔFz"的
> 探测下限。** 它从来不是"我们与参考量差了 38~64 N"。

| # | 主张 | 查证结果 |
|---|---|---|
| 1 | 开放项 C 记的 `38~64 N` 是 z 方向上的**实测缺口** | ❌ **不成立。** 它的唯一出处是 `.superpowers/sdd/runtime-guard-report.md` §3.1.1 与 `Config.h` 的 `FORCE_GUARD_TOL_FORCE_N` 注释块、`ForceCompensation.cpp` 的 `g_guardVote` 注释块；那三处的原话都是"**ΔFz 要到 `tol_M / \|c_s_横向\|` = 38~64 N 量级，力矩通道才有机会把它顶超限**"。我按四份夹具**逐位复现**了这张表（§2.1）。 |
| 2 | 仓库里存在一个 38~64 N 量级的 z 差 | ❌ **不存在。** 三轮 `@720` 数据（**30 行 = 3 轮 × 每轮 10 行**；每轮 10 行 = **5 个不同姿态 × 2 次原地复采**，三轮合计 **14 个不同姿态** —— 第 1 轮与第 2 轮**共用 1 个姿态**，所以三轮的姿态集**不互不相交**）上 `\|comp_z − @720_z\|` 最大 **0.174 N**；三轮 `@576` 上最大 **0.251 N**（§2.2）。 |

| 4 | 第三行"估错"到**实测能分辨的程度** | ❌ **数据排除。** `comp − @720` 的**重力方向响应矩阵**第三行（= `A_臂 − A` 的 z 行）模只有 **0.0078 / 0.0042 / 0.0164 kg**，即 **0.076 / 0.041 / 0.160 N**（§4.2）。这比 38~64 N 小 **240 ~ 400 倍**。 |
| 5 | 两个参考量的 `Fz` 是**两个不同的量** | ✅ **成立**（`comp−@576` 的 z 恒为正 `+0.129 ~ +0.153`，`comp−@720` 的 z 为 `+0.006 ~ −0.082`）。**但它只解释约 0.2 N 的差，解释不了 38~64 N**（§4.3）。 |
| 6 | 换帧（原点/平移）在 z 上的影响 | ❌ **按构造排除**，且实测也排除了：原点平移只能产生 `Δc × F` 形式的**力矩**项，对力分量不做任何事（§4.4）。 |
| 7 | 「Fz 不投票」那条秩 2 依据，在新参考量上**原样成立** | ⚠ **不成立。** 依据的对象是 `@576` 的重力方向响应矩阵 `K` 的奇异值 `[0.212 0.201 0.008]`；我在 `calib_poses_2026-09-20_frozen.txt` 与四份夹具上**逐位复现**了它（`12:38` 夹具给 `[0.212024, 0.201123, 0.008311]`），但**同一量在 `@720` 上不具备"第三行比另两行小 8~15 倍"这个形状**：三轮是 **0.18× / 2.09× / 0.72×**（§5.2）—— 其中 `0.18×` 那一轮只比旧参考量的带（`0.070 ~ 0.094`）高出约 2 倍，而它的分子与 `se` 之比只有约 `2 ~ 3σ`，**单独不定案**；定案的是第 2、3 轮与合计。 |

**⇒ 判决。** 「38~64 N」从来不是模型缺陷，也不是与任何参考量的差；它是**力矩通道**的探测下限。
而**力矩三个分量自 2026-09-21 起已经不投票**（`g_guardVote`）⇒ 那个算法**现在是一道不存在的
门**（`Config.h` 的容差注释块与 `ForceCompensation.cpp` 的 `g_guardVote` 注释块写的就是这一句：
**数字一个都没变** —— 它本来就是"力矩门**若有**，要多大的 z 差才看得见"；变的只是**现在没有
这道门**）。**⇒ 关闭开放项 C。**
**代价与残余**（必须一起读，§7）：`Fz` 不投票这件事**仍然没有替代物**；本判决说的是
"没有文件支持「第三行错了」，而且 38~64 N 这个尺寸不是缺陷的尺寸"，**不是**"z 方向从此有人守"。

## 2. Step 1 —— 现有证据收齐（逐条注明出处）

### 2.1 「38~64 N」的唯一出处 —— 它是什么量

**出处一（原始表）:** `.superpowers/sdd/runtime-guard-report.md` §3.1.1，原话两段：

```
* 力矩通道【理论上】能给 z 力当后盾: z 上的模型误差 ΔFz 会经 c_s 叉乘出一个力矩误差
  Δc × ΔF, 其【横向】分量量级 = |c_s_横向| · ΔFz  (c_s_横向 = sqrt(cs_x² + cs_y²))
* 但 c_s 的横向分量实测【只有 0.47 ~ 0.78 mm】:
  | 采集 | |c_s| (m) | 其中轴向 (m) | |c_s_横向| (m) | tol_M / |c_s_横向| |
  | 12:38 | 0.054555 | 0.054549 | 0.000781 | 38.4 N |
  | 15:25 | 0.055548 | 0.055545 | 0.000499 | 60.1 N |
  | 15:30 | 0.056040 | 0.056037 | 0.000566 | 53.0 N |
  | 15:33 | 0.054677 | 0.054674 | 0.000471 | 63.7 N |
* 而力矩容差 tol_M = 0.03 N·m ⇒ z 力模型误差要到 0.03/0.00047 ~ 0.03/0.00078
  = 【38 ~ 64 N】量级, 力矩通道才有机会把它顶超限
```

**出处二 / 三（已落进生产代码的同一句话）:** `Touch_Client/force/ForceCompensation.cpp` 的
`g_guardVote` 注释块、`Touch_Client/config/Config.h` 的 `FORCE_GUARD_TOL_FORCE_N` 注释块。
两处都写着同一件事，并各自补了一句 2026-09-21 的更新：**力矩三个分量已经不投票**
⇒ 那个算法"现在是一道**不存在的门**"。

**★ 我独立复现了出处一的那张表**（输入 = 四份夹具 + §附 的式子；结果与表内**逐位一致**）：

| 采集 | `\|c_s\|` (mm) | `c_s` (mm，传感器系) | `\|c_s_横向\|` (mm) | `tol_M / \|c_s_横向\|` |
|---|---|---|---|---|
| 12:38 | 54.555020 | (+0.5981, −0.5015, +54.5494) | 0.780572 | **38.43 N** |
| 15:25 | 55.547505 | (−0.2660, +0.4227, +55.5453) | 0.499379 | **60.07 N** |
| 15:30 | 56.039807 | (−0.3977, −0.4025, +56.0370) | 0.565795 | **53.02 N** |
| 15:33 | 54.676456 | (+0.3593, −0.3046, +54.6744) | 0.471061 | **63.69 N** |

（同一跑里算出的四份 `σ(A)` 与前置复核 §7.2 的表**逐位相同**：`0.433855/0.426469/0.407198`、
`0.443856/0.425777/0.396287`、`0.443014/0.423533/0.388369`、`0.435090/0.418759/0.402309`。
⇒ 我的口径与那份**已被独立复核过**的复现口径是同一套。）

**⇒ 结论：「38~64 N」是一个探测下限，不是任何差。** 它的定义是
`tol_M / |c_s_横向|`：**力矩通道**要把一个 z 力误差顶到 `tol_M` 之上，那个误差得有多大。
`38.4 / 63.7` 正是 `0.03 / 0.000781` 与 `0.03 / 0.000471`。

### 2.2 仓库里有没有一个 38~64 N 量级的 z 差 —— 没有

**出处:** `Touch_Client/tests/fixtures/calib_poses_2026-09-20_frozen.txt` 的三段 `@720` 轮次。口径与前置复核 §5④ 相同

**我复算的轮均值与前置复核 §2.1 的表逐位相同**（`comp−@576` 的 `Fx` 2.260/1.806/2.074 等），
所以下面这两列可以当作与那份复核同一口径。

| 轮次 | `\|comp_z − @576_z\|` 最大 | 均值 | `\|comp_z − @720_z\|` 最大 | 均值 |
|---|---|---|---|---|
| 21:58:46 | 0.196 N | +0.129 N | **0.085 N** | +0.006 N |
| 22:12:28 | 0.201 N | +0.131 N | **0.174 N** | −0.082 N |
| 22:18:42 | 0.251 N | +0.153 N | **0.144 N** | −0.058 N |

⇒ 两个参考量下，**z 的差都只有零点几牛**，没有 38~64 N 量级的东西。

—— 闸门真正的拒绝量在那两路上，不在 z 上。）

### 2.3 z 方向的"模型侧"量有多大 —— 这是判「第三行估错」的尺子

**出处:** `Touch_Client/tests/fixtures/force_calib_2026-09-20_frozen.json`（已安装 `version 3`）与 `calib_report_2026-09-20_frozen.md` 各节。

| 量 | 值 | 说明 |
|---|---|---|
| 已安装 `A` 的三行模 | 0.414318 / 0.423105 / **0.410561** kg | 第三行 = `[−0.0055097, −0.0098905, −0.4104049]` |
| 已安装 `A` 的 `σ` | 0.425955 / 0.416137 / 0.405746 kg | 各向同性比 1.0498 ⇒ 近 `m·R` |
| 质量尺度 `m = \|det A\|^(1/3)` | 0.415864 kg | ⇒ 整条链的重力 = **4.080 N** |

**⇒ 第三行整行**在重力方向上的最大贡献 = `0.410561 × 9.81` = **4.028 N**。

**⇒ 算术判决:** `38.4 / 4.028 = 9.5`、`63.7 / 4.028 = 15.8`。
**「A 的第三行估错了 38~64 N」这句话要求这一行是实测值的 9~16 倍（模 3.9 ~ 6.5 kg），
或者要求整条链的重力有几十牛。** 前者与四份夹具、`calib_report_2026-09-20_frozen.md` 的**每次采集各一次拟合**
都不相容（§4.1），
后者与"这是 0.416 kg 的工具链"直接矛盾。

## 3. Step 2 —— 候选与它们的可判别 signature

对每个候选：**若它是真的，数据上该看到什么**。写不出 signature 的**标"不可判别"**。

| # | 候选 | 可判别 signature |
|---|---|---|
| **甲** | **`A` 的第三行本身估错** | 把 `d ≡ comp − 参考量` 投影到重力方向：`d = c + K·g`，则 `K` 的**第三行** = `A_参考 − A` 的 z 行，其模 ≈ 第三行的误差（kg）。**它必须显著非零，且量级对得上**（38~64 N ⇒ `3.9 ~ 6.5 kg`）。噪声下限由**同姿态复采**给（5 对/轮）。 |
| **乙** | **`@576` 的 `Fz` 与 `@720` 的 `Fz` 是两个不同的量** | 两者的 z 残差应**系统性不同**（符号/幅度/对姿态的响应都不一样）：`comp−@576` 的 z 与 `comp−@720` 的 z **倾向于**不同号（实测 **3 轮里 2 轮**不同号；第 1 轮两者同为正）、且两者 `K` 的 z 行不同。**但**两者之差本身必须**与 z 的物理量级相容**（这里只有几牛），**不足以解释 38~64 N**。 |

| **丁** | **参考量自己的 z 通道坏（秩 2）** ⇒ 比较无信息 | 参考量自身的 `K` 应出现**"第三行比另两行小一个量级"**的形状（`@576` 的实测形状）；且 `comp − 参考量` 的 `K` z 行**继承同一种抑制**。⇒ 若新参考量没有这个形状，则这条理由**不能原样搬过去**。 |
| **戊** | **z 上有一个我们没建模的力**（例如机械臂 z 向补偿特性） | 应表现为 `@1304 − b_F − A·g` 的 z 随姿态**有结构**，且这个结构在 `@576` 与 `@720` 上**同向同幅**（因为它是物理量，不是参考量特性）。 |
| **己** | 「38~64 N 本身是一个 z 差」 | **不可判别** —— 它不是可判别的候选，因为它的出处是一句**算式**（§2.1），不是一次测量。**任何"数据上该看到什么"都写不出来。** |

丁是 §5 的复测题目；乙的**前半**（是不是两个量）能判、**后半**（能不能解释 38~64 N）用算术判。

## 附: 复现方法（照此可重跑；本文件每个"我复现"都出自这里）

**① 重力**（唯一实现，符号约定照 `TcpCalibration`）: 用 `ψ = 0` 的
`gravitySensorFrameAtYaw(pose, 0.0)` ⇒
`g = 9.81 · (−sin ry, cos ry·sin rx, cos ry·cos rx)`。

**② 本地补偿**（静止 ⇒ 无惯性项）:
```
comp[0..2] = @1304[0..2] − b_F − A·g
comp[3..5] = @1304[3..5] − b_M − (c_s × (A·g))
A, b_F, b_M, c_s 取自 Touch_Client/tests/fixtures/force_calib_2026-09-20_frozen.json
```

**③ 重力方向响应矩阵 `K`**（§5 用的就是它）:
```
每个分量 a:  y_a(pose_i) = c_a + k_a · g(pose_i)     # 常数 + g(三个分量)
K = [k_x; k_y; k_z]（3×3, 行 = 力分量）
σ(K) = K 的奇异值（降序, 量纲 kg）；行模 = ‖k_a‖
```

**④ 差量的响应**（§4.2）: 把 ③ 的 `y` 换成 `d ≡ comp − 参考量`，
噪声 σ 由**同姿态复采对** `d[2j] − d[2j+1]` 估，`se(k) = sqrt(σ²·(XᵀX)⁻¹)`，`X = [1, g]`。
**⚠ 两个约定必须一起读（口径说明见 §4.2）:**
- σ 取 **`rms(对差)/2`**（对零点）；常规两样口径（对均值、`ddof=1`、除 `√2`）在同一批差上
  是 `0.0438 / 0.0152 / 0.0299 N`，两者期望相差 `√2`。
- 表里的 `se` 用**同一个 z 的 σ** 摊到三个分量上（三个分量的 σ 没有分开估）；
  若逐分量估 σ，`t` 会变（`§4.5` 给了两种口径的数）。**逐分量那一组的口径是**：
  三个分量的 σ 各自估（同一批复采对、同一个 `rms/2`），并**按分量一一对应**用 ——
  `g_x` 的系数配 x 分量的 σ、`g_y` 配 y、`g_z` 配 z（即 `se_j = σ_j·√[(XᵀX)⁻¹]_jj`），
  再对该行三个分量取最大。`§4.5` 的 `3.33 / 2.53 / 13.39` 就是按这一条复算的
  （复算值 `3.3293 / 2.5253 / 13.3875`）。
