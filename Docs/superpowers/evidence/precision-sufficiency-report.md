## 1. 合成采集的构造

- **10 个姿态、5 个原地重复对**，镜像 `calib_poses.txt` 的 15:33:38 块；姿态几何逐列抄自该块。
- **真值参数**取 run 003 的拟合结果（分析文档 §附）：`A`、`b_F = (-18.43445,-2.17091,+0.78958)`、
  `b_M = (-0.16701,+0.57753,-0.02472)`、`c_s = (+0.329,-0.321,+54.682) mm`。
- `g = TcpCalibration::gravitySensorFrameAtYaw(pose, 0.0)`,  `F = b_F + A·g`,
  `M = b_M + c_s × (A·g)`。
- **逐姿态噪声**：按文件里那一行的 `sd` 与 `N`，每姿态抽 `N` 个样本再取均值
  （方差用 `main.cpp` 同一套无偏 `sampleVar`，即除以 N−1）。
- **原地重复**：第二次访问的姿态 = 第一次 + 小扰动（默认 ±0.05°/轴，另做 0.01–0.2° 的扫描），
  力/力矩**由扰动后的姿态重新生成**。

**为什么真值要"文件位数 + 亚位偏移"**：文件里的数字本身就是舍入过的。若令真值 = 文件数字，
则"舍入到同样位数"是恒等操作，实验什么都证不了。所以真值 = 文件值 + 一个**固定的**亚位偏移
（rpy < 0.04°、xyz < 4e-4 mm、sd < 4e-5），小到再舍入回文件位数就**逐位还原成文件值**。
于是粗格子的破坏被如实测出，而不是被抵消。三个独立的 RNG 流（偏移 / 扰动 / 样本）互相不干扰。

**舍入用 `snprintf(生产格式串) + strtod` 实现** —— 与 `logPoseData` 的 `fprintf` 和重放解析器
逐字同源，不是"自己写个 round"。

**姿态布局**: `pose = [x,y,z,rx,ry,rz]`，只有 `pose[3..5]` 进重力模型
（`flangeGravity` 读 `R[6],R[7],R[8]`）。

**恒等式 1: `rz` 根本不进重力模型。** `g = Rᵀ·(0,0,G)` 是 `R = Rz(rz)·Ry(ry)·Rx(rx)` 的**第三行**，
而 `Rz` 的第三行是 `[0,0,1]` —— `rz` 精确抵消。`+.5°` 与 `+0°` 逐位相同。
→ **pose 的第三列 `rz` 无论写几位都与 `fitRaw` 无关**。

**恒等式 2: `rx` 的【共同】偏移被 `A` 精确吸收。** 有恒等式 `g(rx+d) = Rx(d)·g(rx)`（精确，
不是一阶），所以"所有姿态的 rx 同时加 d"就是"所有 `g_i` 同乘一个固定旋转"，
而 `A` 是**全自由 3×3** —— 完美吸收。`+0.5° common` 与 `+0°` 逐位相同（表里那一列就是证明）。
→ **姿态角度的【绝对】精度完全不重要；只有它逐姿态的【变化】才重要。**

**这两条影响了判决的读法**：TcpCalibration 注释里"0.05° 台阶 ⇒ 2.1e-3 N 逐姿态系统性误差，

## 5. 反例、保留意见与需要上报的点

### 5.1 两个恒等式使得"姿态精度"这条论证的写法需要修正（不是结论错，是理由错）

`TcpCalibration` / `logPoseData` 的注释用"`0.05°` 台阶 ⇒ `9.81·sin(0.05°/√3)·0.42 ≈ 2.1e-3 N`
逐姿态系统性误差，吃掉 `rmsF` 的 14%"来论证 `%.1f → %.3f`。

- **理由不成立**：a) `rz` 不进模型；b) `rx` 的**共同**分量被 `A` 精确吸收。
  "台阶"这个词暗示的是共同偏移，而共同偏移完全无害。
- **结论仍然正确**：真实的 `%.1f` 舍入误差是**逐姿态不同**的，那才进结果。量到的是
  `rmsForceN` 变化 **−1.39%**（不是 14%），`chi2ForceRatio` **−7.33%**，`chi2RepForceRatio` **−8.05%**。
- **建议**（仅文字）：把理由改成"逐姿态舍入误差不可被 `A` 吸收"并引用量到的 8%，
  而不是"2.1e-3 N / 14%"。

### 5.2 力矩列的论证方向对、量级错——真正的元凶是**均值列**，不是 sd 列

注释的力矩论证把重点放在 sd 列（`%.4f` 台阶 1e-4 = `sdM` 的 8% → 方差 16% → 进尺子底噪）。
实测归因：

| 单独舍入 | `lackOfFitMomentRatio` | `repeatSigmaM[1]` | `cS[0]` |
|---|---|---|---|
| 只有 sd `%.4f` | −0.44% | +0.49% | 0.000% |
| 只有 pose `%.1f` | +0.12% | 0.000% | 0.000% |
| **只有均值 `%.3f`** | **−52.45%** | **+34.95%** | **−8.14%** |
| 三者同时（= (b)） | −52.38% | +34.96% | −8.14% |

**sd 列只贡献 0.49%，均值列贡献全部。** 而且机制**不是**注释里写的 `q²/6` 方差项：

- `q = 1e-3` 时 `q²/6 = 1.7e-7`，与 `floorM ≈ 2e-7` 同量级 → 按注释的算法只会得到一个温和效果。
- 真正的机制是：**重复对的差值 `d` 本身被量化了**。真实 `|d| ~ 2e-4 N·m`，而格距 `q = 1e-3` —— 
  `q` 比 `d` **大 5 倍**，于是 `d` 被替换成 `0` 或 `±1e-3` 这样的粗格子值，
  尺子的 `σ_sys,M` 于是由**量化**而非物理决定。量到的膨胀是 **+23% ~ +35%**。

→ **改 `%.4f → %.9f` 是合理的（0.49% → 0.0006%），但它不是这次缺口的成因；
真正的成因是均值列的 `%.3f → %.9f`。** 这一点如果写进注释会更准确。

### 5.3 "缺口是 2×"这个说法在三个采集上并不一致 —— 只有 run 003 被本实验复现

档案记录的三对数字是 `6.97 vs 5.359`（×1.30）、`18.36 vs 20.51`（×0.895）、
`33.74 vs 61.22`（×0.551）。**方向和倍率都不一致**，所以不能笼统说"旧精度造成 2× 缺口"。

本实验复现了 run 003 那一对（单次实现：合成 2.019 → 0.962 = **×0.476**，档案 **×0.551**），
**但这是一个实现的结果**：12 个种子下 `lackOfFitMomentRatio` 的 (b) 偏差是 **−41% ~ +107%**，
4/12 为正。所以"复现了 run 003 那一对"这句话的**稳健性只在备择侧成立**（见 §3 的分母论证：
分母单项预测 −21% ~ −45%，与档案的 −45% 吻合）。

另外两对（×1.30、×0.895）的成因**未被本实验覆盖**。它们与 run 003 的方向都不同，
说明"控制台 vs 夹具重放"的差异**不是单一机制**，或者那两次采集的复现性/姿态扰动本就不同。
**建议措辞**：把"从前它们差 2 倍以上"收敛到"run 003 那一次差 0.55 倍；本次实验复现了
该次的分母机制（预测 −21%~−45%），但另外两次的成因未查清"。

### 5.4 保真缺口（必须声明，但不影响判决）

合成数据的力矩通道是**模型精确自洽**的，所以 (a) 的 `lackOfFitMomentRatio = 2.019`
落在**零分布**（门限 5.106），而实机 run 003 是 **61.22**（远在备择）。
所以本实验**没有**直接测量"量化对 61 量级的统计量做了什么"。

**为什么这不影响判决**：(b) 的破坏是通过**分母** `σ_rep,M²` 起作用的（膨胀 1.27–1.82 倍），
分母与统计量落在哪个位置无关；把同一个因子（(b)/(a) = 0.476）应用到实机的 61.22 得 ≈29.2，
与记到的 33.74 同量级。但严格地说，这是"机制外推"，不是"直接测量"。
**若要闭环，需要在实机上重跑一次并比对落盘重放** —— 这也正是注释里"这条规矩怎么验收"所要求的。

### 5.5 未被覆盖的情形

- **`%.4f` 与 `%.3f` 之间的 sd 列**：阶梯显示 `%.4f` 只有 2× 余量（0.4877%）。若日后有人把 sd 列
  也降回 `%.3f`，会到 4.8% —— **不满足**。当前选择是安全的。
- **只有 1 对重复姿态**（R=1）时尺子自由度低得多，(b) 的破坏会更大，(c) 的余量更小。
  本实验用的是 5 对（与 15:33:38 一致）。**未测** R=1 的情形。
- **姿态数不是 10** 的情形未测。
- **接受/拒绝的翻转**：合成数据是模型自洽的，三个变体都 `return true`，所以"量化是否翻转最终判决"
  在 run-003 形状的数据上**没有**被直接测到。但阶梯里均值列 `%.2f` 给出 `ok=0`，
  种子扫描里 seed 255000 的 (b) 是 `ok=0` 而 (c) 是 `ok=1` —— 说明翻转是可能的，
  只是不在本次主对照的工况里。
