# 控制台 vs 文件重放 —— 一致性验证 (采集 2026-09-19 18:49:55)

**任务**: 验证"把最新一块 `calib_poses.txt` 重放回**生产** `PayloadCalibration::fitRaw`,
能否复现控制台打印的统计量"。这是落盘精度修好之后（力矩均值 `%.3f → %.9f`、姿态角
`%.1f → %.3f`、逐姿态 sd `%.4f → %.9f`，见 `main.cpp:792-832`，已随 HEAD `681d811` 提交）
的**第一份**采集，所以这个主张第一次可测。

**没有改动任何生产文件**；探针与全部产物在仓库外 `D:\tmp\replaycheck\`。
`calib_poses.txt` / `calib_report.md` 只读。

## 结论 (先说)

**是 —— 重放复现了控制台，但要把两种读法分开，下面都说清楚。**

| 读法 | 结论 |
|---|---|
| **操作意义**（判据量 / 判决 / 尺子 / 物理量） | **是**。每个判据量都与打印值相容；判决逐项一致（力矩门拒、力门过、总判决 = 拒绝）。旧采集那种 **×1.30 / ×0.895 / ×0.551** 的缺口在本次采集**不再出现**：最坏相对差 **3.68e-4**（改善约 1200×）。 |
| **逐位意义**（打印出来的每一位都相同） | **不是**。59 个被比量里 **17 个**最后一位/几位不同，全部是**依赖姿态角**的那一批（`A` 的 9 个元素、`b_F`、`b_M` 的一支、`cond`、`isotropy`、`rmsForceN`、力 `χ²/dof`）。 |

**残差已定量归因**：剩下的差**全部**来自姿态角仍只存到 `%.3f`（0.001°）这一列。
400 次"按各自台阶还原抽样"表明：控制台的打印箱与还原区间**全部相交**（9/9），
而**只扰动姿态角**就复现出同样宽的区间、**只扰动均值/sd 列**区间宽度**为零**。
这一结论与 `precision-sufficiency-report.md`（在合成数据上做的）**方向与量级一致**
（那里报 0.032% 以内 / 最坏 0.184%；这里实测最坏 0.037%）。

**一句话**：落盘精度修复把**主导项**（力矩均值）去掉了；剩下的**唯一**限制列是姿态角
（`%.3f`）。要让重放**逐位**复现控制台，还得给姿态角加位数。

**顺带撞上的（不是本任务的结论，但值得知道）**：18:49:55 那一块的屏幕上，"尺子"这个名字
出现了**两次数、两个值**（块头 `0.0208 N`、块尾 `0.1349 N`），因为两行用了**不同的式子**
（块尾漏了平方）。**两个数本探针都复现了**（各自对自己那一行）。该显示 bug 在本任务进行期间
已被另一个会话在 `fd4eead` 里修掉；`PayloadCalibration.cpp` **未被任何人改动**，
所以重放用的 `fitRaw` 与采集当时是同一份。详见 §2 末。

## 3. 容差与理由

**用的容差 = 控制台打印表示的【半个 ulp】**

理由：`printf("%.4g"/"%.6f"/"%.7f", x)` 打印的是 `round_to_nearest(x)`，所以
`|x − 打印值| ≤ 半 ulp` 是**恒成立的**（不是估计）。于是"重放 = 控制台"最严格的可判定
表述就是：`|重放 − 打印值| ≤ 半 ulp`，即**重放值四舍五入后打印出来的每一位都与控制台相同**。
按各量的实际格式取：

| 格式 | 半 ulp |
|---|---|
| `A` 的 `%+.7f` | 5e-8 |
| `b_F` / `b_M` 的 `%+.5f` | 5e-6 |
| `m` / `rms*` 的 `%.6f` | 5e-7 |
| `cond` 的 `%.4f` | 5e-5 |
| `isotropy` 的 `%.5f` | 5e-6 |
| `c_s` 的 `%+.3f` | 5e-4（mm，绝对） |
| 统计量与门限的 `%.4g` | 该值的 4 位有效数字半步（如 0.6508 → 5e-5；27.23 → 5e-3） |
| `σ_rep` / `σ_sys` 的 `%.4f` | 5e-5（绝对） |

**这是一个很紧的容差**，紧到"文件里还剩下的那一级台阶"都会让它 FAIL（见 §4）。
我没有放松它 —— 反而把 FAIL 的**数量与归因**都列出来了，因为"紧到 FAIL"本身就是本次的发现。

**同时也给一个"相容"判据**（§4 的表）：控制台的**打印箱** `[c−u, c+u]` 与"文件台阶
允许的重放区间"**是否相交**。它回答的是另一个问题：*控制台那个数，在文件所记录的精度下
能不能产生出来*。两种读法都要看：前者问"能不能逐位复现"，后者问"差是不是文件自带的"。

## 4. 归因：剩下的差是谁造成的（mode `c`）

做法与 `moment-gate-calibration-report.md` §1.4 同法：把每个带小数的数按**它自己文本里
的小数位数**还原抽样一次（`v + U(−q/2, +q/2)`），再驱动**同一个生产 `fitRaw`**，400 次。
台阶是自动取的：姿态角与位置 **3 位小数 → q = 1e-3**；力/力矩均值与 sd **9 位小数 → q ≈ 0**。

**（1）全部小数位都参与还原**

| 量 | 控制台 | 重放（文件原样） | 还原区间 [min, max] | 差 / 打印台阶 | 打印箱与区间相交? |
|---|---|---|---|---|---|
| `chi2RepForceRatio` | 0.6508 | 0.650928 | [0.649567, 0.652501] | 2.56 | **是** |
| `rmsForceN` | 0.01155 | 0.0115531 | [0.0115455, 0.0115605] | 6.25 | **是** |
| `cond` | 34.748 | 34.7481 | [34.7476, 34.7487] | 2.26 | **是** |
| `isotropy` | 1.07275 | 1.07274 | [1.07272, 1.07276] | 2.25 | **是** |
| `m` | 0.420847 | 0.420847 | [0.420845, 0.420850] | 0.26 | **是** |
| `A[0]` | 0.3636941 | 0.3636966 | [0.3636921, 0.3637011] | 50.11 | **是** |
| `A[4]` | 0.3783268 | 0.3783239 | [0.3783184, 0.3783299] | 57.23 | **是** |
| `b_F[1]` | −2.12070 | −2.120722 | [−2.120781, −2.120661] | 4.32 | **是** |
| `lackOfFitMomentRatio` | 27.23 | 27.2338 | [27.2335, 27.2342] | **0.76** | **是** |

**9/9 相交**。

**（2）只扰动姿态角（列 1,2,3）** —— 区间下沿/上沿与 (1) **几乎逐位相同**
（如 `chi2RepForceRatio` [0.649397, 0.652185] 对 [0.649567, 0.652501]）。

**（3）只扰动均值/sd 列（列 13..25，现在是 9 位小数）** —— **区间宽度为零**（q=1e-9
在 double 上不动）：这一批数**已经不再是误差来源**。

⇒ **结论**：本次采集的残余差**全部**来自姿态角仍存到 `%.3f`（0.001°）。均值/sd 列
（今天修的那三处）**已经完全够用**。

**为什么 `A` 的"差/打印台阶"高达 50~57 而 `m` 只有 0.26**：不是 `A` 更差，而是 `A` 的
打印格式 `%+.7f` 的格子（5e-8）**远细于**文件台阶（0.001°）能保证的分辨力
（≈2e-6）。**打印比存储细 —— 这就是"逐位复现做不到"的全部原因。**

## 6. 没能验证 / 边界

1. **控制台那份"真值"是打印值，不是内存值。** 本报告比较的是
   `calib_report.md` 上**打印出来的**数；"重放在逐位意义下是否等于当年内存里的 double"
   **无法验证** —— 那需要当时的进程。§4 的"打印箱与还原区间相交"是对这个缺口的
   能力上限：它证的是"差被文件自带的不确定性解释了"，不是"差等于零"。
2. **只有一份新采集。** 落盘精度修复后**只此一块**（18:49:55）。同一结论在别的姿态组、
   别的 `A`/`c_s` 上是否同样成立**没有测**。（`precision-sufficiency-report.md` 用合成
   数据扫过 12 组噪声，但那是合成。）
3. **18:46:03 那一块（11 姿态 / 8 对）没测。** 任务只要最新一块；那一块的重复对下标
   是 `1,2,3,4,6,7,8,9`（含相邻对），值得单独看一眼。
4. **`calib_report.md` 不是机器产出的。** 表里的控制台值是我**转抄**的，7 位小数的 `A`
   那一批如果有人抄错一位，本报告的对应行就会假 FAIL。可信度最高的两组是
   `σ_rep`/门限/判决（多家文档互相印证）。
5. **本任务进行期间 `main.cpp` 被另一个会话改过两次**（HEAD 从 `681d811` 移到 `fd4eead`）：
   拒绝行的措辞改了，**并且把 `yardF/yardM` 那个漏平方的显示 bug 修了**（见 §2 末）。
