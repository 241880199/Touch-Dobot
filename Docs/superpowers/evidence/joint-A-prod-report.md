## 6. 一处必须点名的改动：`paramSigma` 的 A / b_F 块

`A` 换成 `A_joint` 之后，**照旧报力通道线性解的 `CF·s²` 就是在用一个描述别的估计器的数**
（它按 `sqrt(diag(CF)·ssF/dofF)` 算，而那个系统已经不是产出 `out.A` 的系统）。所以：

```
联合路径  : paramSigma[0..11] = sqrt(diag((JᵀWJ)⁻¹)) · sqrt(χ²_W/(6n−18))
非联合路径: 一个字没动 (照旧 CF·s2F)
c_s / b_M : 两条路都照旧 CM·s2M (给定 A 之后的 6 参数系统 —— 它仍然是产出它们的系统)
```
`(JᵀWJ)⁻¹` 是**权重取实测方差**的那个协方差（模型对时就是它自己），再乘一个与模块原本口径
**同形**的过散因子 `χ²_W/dof`（原本那个是 `SSR/(方程数−参数数)`）。
`paramSigma` **不参与任何接受/拒绝判据**（`RawFit` 的说明、`main.cpp:1344` 那一段都写着），
它只进日志列与诊断屏 —— **日志的【列】没有动**，动的是这一列的值（`A` 本来就变了）。
18:49:55 上它给 `(0.00158 0.00104 0.00130 / … / 0.00686 0.00557 0.00492)`。

## 11. 没能验证的地方 / 顾虑（诚实清单）

1. **`A_joint` 的两把门数值，生产现在是【自己报】的了** —— 这一条比离线研究强（它只能靠复算件）。
   但 ⚠ **`[S6]` 融合那一档、以及 §9.2 的 `k` 扫，仍然只有离线复算件一个来源**：生产里
   没有第二条路径能造出"另一个权重口径下的 `A`"。§9 的敏感性因此是**引用的**，不是本实现实测的。
2. **`Σ_A` 与 `Â` 不再出自同一个估计器**（§8.2）。我只量化了它对 `e`/门限的影响
   （−0.22%~+0.04%），**没有量化它对"力矩门该不该用这把 `e`"这件事的影响**。
   这是本次改动留下的、我没有闭环的一处。
3. **联合估计让一个错的力矩模型能污染 `A`**（§8.1，实测 `1.68×` + 力门同时拒）。
   我**没有**量化"多大的力矩结构错才会把力门拖翻"这条边界，也没有做"污染后质量尺度是否
   仍然物理"的系统检查。这条代价是真实的，方向是安全侧（错模型仍被拒），但边界未知。
4. **`d` 判据的数字是夹具口径**（§5）：`13.757 mm` 这个具体值在新精度采集上可能会动
   （已定量：要挪 4 倍以上才可能翻符号）。
5. **只有四份可用采集**（`18:46:03` 生产自己秩亏、`12:38:19` 没有重复对）。四份上的结论
   不等于"这个估计器在所有 `A` 上都对"。
6. **`paramSigma` 的 A 块换了口径**（§6）：`(JᵀWJ)⁻¹·χ²_W/dof`。我认为这是**描述 `out.A` 的
   唯一自洽选择**，但**没有**独立验证"`paramSigma` 报的 1σ 与真实的 A 误差分布相符"
   （那需要蒙卡，本任务没做）。它不参与任何判据。
7. **没有跑机械臂、没有碰 `Touch_Client.exe`、没有结束任何进程**（`build.bat` 一次 `LNK1168`
   都没出）。所有探针产物在 `D:\tmp\jointAprod\`、`D:\tmp\limitprod\out_e_new.txt`（仓库外）。
